架构总览

这页回答三个问题：代码怎么跑起来的、数据怎么流动的、升级版本要动哪几处。写任何代码之前先读这页。

执行模型（最重要的两件事）

1. 没有 iframe，插件和桌面住在同一个文档里

用户点击图标时，plugin-manager.js 把插件的三个文件拉下来注入宿主主文档： HTML 片段 insertAdjacentHTML 进 body，样式加成 <link>，脚本以全新 URL 注入为 <script type="module">。 所以你的插件能摸到整个桌面的 DOM，也能摸到全部 window.__* 全局钩子——方便，也意味着你要自觉（选择器带自己的类名前缀、卸载时清理全局注册）。

2. 冷加载：启动只读清单，点击才加载内容

开机时系统只 fetch 全部内置插件的 manifest.json（清单即 BUILTIN_IDS，带 ?v=VERSION 缓存戳）建立注册表， 再从 IndexedDB 还原用户装过的 ZIP 插件，最后广播 plugins-ready。程序坞、启动台、商店都是监听这个事件才渲染的。 你的 style.css / index.html / script.js 要等用户点击图标才被拉取。细节与两条硬约束见冷加载机制。

模块图（内核依赖方向，自上而下被消费）

settings.js（最底，不 import 任何内核模块）
   ▲
osfs.js（文件存储：单一根 + virtual/disk 双后端）   i18n.js / zindex.js / log.js（叶子模块）
   ▲
app-registry.js（应用注册表 + broadcast 事件总线）
   ▲
plugin-manager.js（装载 / 卸载 / 图标解析 / ZIP 安装）   api-grants.js（权限账本）
   ▲
finderbar.js（顶栏菜单）· dock.js · window-manager.js · controlcenter.js
   ▲
mods/*（内置插件，清单见 BUILTIN_IDS；office 是多应用套件：word / excel / ppt）

记这张图的意义：下层不知道上层的存在。你写插件时可以 import 任何下层模块，但永远不要反过来——内核模块不会、也不该 import 你的插件。

数据流三条主路

路写入方你怎么收到变化典型消费方
设置window.__settings.set(key, v)（唯一写入入口）document 事件 settings-changed，或 __settings.on(key, fn)程序坞 / 控制中心 / 表面 / 音效等 owner 模块 + 你的插件
日志window.__log.info/warn/error/debug（console.* 也被自动归档）不广播；进内核缓冲，跨刷新留存顶栏「调试 → 查看运行记录」查询 / 导出
事件总线Deskly.bus.emit(topic, data) 或内核 app-registry.broadcast()同名 CustomEvent（document 派发、bubbles: true，window 上也能收到）插件间通知、内核生命周期广播

缓存戳规则（为什么资源后面有个 ?v=）

资源戳值为什么
插件 manifest.json（启动注册）?v=VERSION每次发布自动失效，同一版本内复用缓存
宿主 index.html 里的 script / css?v=VERSION（当前 15 处）升级 = 整站资源一起失效
插件的 style.css / index.html内置插件 ?v=VERSION；商店 ZIP 插件 Date.now()ZIP 允许同 id 覆盖安装，必须每次拿新的
插件入口 script.js永远 Date.now()（+ 序号）入口顶层要重跑 init()，URL 稳定会被 ES module 缓存命中，二次打开就不执行了
红线 ES module 的 import 说明符永远不带 ?v=。带与不带会被浏览器当成两个模块， 内核模块被求值两次 → 两份状态互相覆盖全局钩子（设置、日志、注册表全部分裂）。这条 deep-check 会拦。

升版本要同步的三处

  1. src/javascripts/version.js 的 VERSION（资源戳与「关于本机」都取它）；
  2. 扩展根 manifest.json 的 version 与 version_name；
  3. 根 index.html 里全部 ?v= 串（当前 15 处）。

然后在 docs/产品更新信息.md 头部按既有格式补一条更新记录。详见版本与更新。

「没有 iframe」的两条推论

  • 你的 document、window 就是桌面本身。别假设独占 DOM；也别调用 window.location.reload()——那只会重载整个桌面。
  • 内置插件直接 import 内核模块（../../src/javascripts/xxx.js）是允许且鼓励的； 商店 ZIP 插件由 sw.js（Service Worker）拦截 ./mods/<id>/ 路径、从 IndexedDB 回源，拿到同等待遇。 能力边界由 manifest.permissions + api-grants.js 账本约束，见 Deskly。
