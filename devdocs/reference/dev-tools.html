开发自检工具

几个 Node 脚本 + 应用内自检。全绿 = 退出码 0。文中括号里的数量是 2026-11-03 的实测输出，随代码增长而变，别把数字当契约。

这是什么

项目没有构建链，浏览器是唯一运行时。能在磁盘上查出来的错，就不该等肉眼在浏览器里撞——这些脚本就是干这个的。 仓库没有 package.json（无构建设计），Node 20+ 直接跑；Node 18 需要临时建一个 { "type": "module" } 的 package.json（跑完删掉），否则动态 import 项目 .js 会按 CJS 解析报错。

脚本一览

脚本查什么什么时候跑
node dev/static-check.mjs 不执行模块的磁盘一致性，分 8 节：①② import 说明符指向的文件存在、说明符与 <script src> 上没误挂 ?v=； ③ 代码/HTML 引用的 assets 资源真实存在；④ 四语言包键位齐、data-i18n 指向的键存在、插件面板 paneId 与注册表对齐； ⑤ 模糊值必须走系统令牌；⑤b 墙纸着色必须乘 --tint-strength；⑥ manifest 声明的文件在插件目录里； ⑦ permissions 三方对齐（PERMISSION_NAMES / LABELS / 各 manifest 声明）；⑧ 设置文案风格 + 术语禁用词（glossary.md） 新增插件、改名或移动资源、动文案键、改 backdrop-filter / 墙纸着色规则之后
node --experimental-vm-modules dev/deep-check.mjs 深度静态审计：全部 JS 模块的 import 说明符与导出符号表（模块与 import 数量以脚本输出为准） 动了内核模块结构之后
node dev/settings-fulltest.mjs 每一条设置项：默认值合法、落盘文本、读回一致、非法值拒绝/钳制、reset、与 owner 历史键逐字一致、 pane/control 与系统设置注册表对齐（项数以脚本输出为准） 增删设置项、改 pane/control 之后
node dev/settings-harness.mjs 设置中枢 + 日志系统本身的行为（槽名推导、on/off、钳制、拒绝、jsonPath、订阅退订、门槛、留存、缓冲上限） 动过 settings.js / log.js 之后
node dev/osfs-check.mjs OSFS 双后端行为（move / ConflictError / 顶层保护 / scope 沙箱） 动过 osfs.js / trash.js 之后
node dev/package-plugin.mjs <id> 导出商店 ZIP（打包即校验：id 与目录名一致、依赖落在插件目录内、宿主依赖存在） 发布插件时
node dev/genie-check.mjs 最小化「神奇效果」的几何自动化校验 动过最小化动画之后
node dev/calc-check.mjs（含 convert / programmer 两个变体） 计算器运算逻辑回归 动过 mods/calculator 之后
node dev/store-check.mjs 商店逻辑自检（注意：Node 18 下 vm.SyntheticModule 不可用会失败——环境问题，非代码错） 动过 store-api.js 之后
node dev/build-manual-content.mjs 重建手册（manual）内容索引 改过手册内容之后

应用内自检（跑在真实浏览器存储上）

  • runSelfTest()（debug.js）：遍历 settings.list()，逐项「写探针值 → 回读比对 → 查存储槽 → 判 isDefault → 还原用户原值」，弹窗报告并可跳运行记录。
  • 顶栏「调试」菜单：查看运行记录 / 清空 / 导出 / 复制 / 切门槛 / 重载当前插件（验证 plugin-unload 是否清干净）/ 输出设置表 / 层级体检。
  • 「调试」菜单由 debug.developerMode 设置项门控（只门控菜单显隐，不门控日志系统本身）。
