多语言 i18n

四语（zh-CN / en / ja-JP / cat「萌猫语言」= 中文+喵）；插件自带文案走 registerMessages，不碰内核语言包。

用法

i18n 不是全局对象，按站内惯例 import：

import { i18n } from '../../src/javascripts/i18n.js';
方法说明
t(key, fallback)点分路径取值；缺失回退 fallback（每个调用都要带字面量兜底——static-check 核对「无兜底调用」）
hasKey(key)当前语言（含插件注册文案）里有没有这个键
getSupportedLanguages()支持语言表；别在界面硬编码四门语言
getLanguage() / setLanguage(lang)当前代号 / 切换并持久化、重刷界面（越界代号抛错）
applyTranslations(root?)对新注入子树应用 data-i18n
registerMessages(lang, obj) / registerMessagesAll(byLang)注册插件自带文案，返回并入叶子键数
onChange(fn)订阅语言切换（回调收新代号，返回退订函数；plugin-unload 里记得 off()）

插件自带文案（关键行为）

i18n.registerMessagesAll({
  "zh-CN": { myPlugin: { title: "我的插件", run: "运行" } },
  en:      { myPlugin: { title: "My Plugin", run: "Run" } },
});
const title = i18n.t("myPlugin.title", "我的插件");   // 缺键靠 fallback，界面不会空
  • 插件文案写进独立的 pluginMessages 表，生效字典 = 「内核包为底 + 插件包叠上」深合并—— 内核重新拉包 / 切语言都不会抹掉插件键，内核改同命名空间的某个键也不会清空你的兄弟键；
  • 注册与内核加载先后无关（语言包没到位也会先建条目）；
  • 四语齐备是规约：仓库惯例是四份都写（cat = 萌猫语言，中文加「喵」尾）；只写两语会让其余语言落到兜底文案。

构建时文案要随语言重建

下拉选项、标签数组这类「构建时算出来」的文案必须订阅 onChange 重建， 否则会永远冻在切换前的语言上（旧版缺陷）。动态键拼接（t("a." + x)）会被 static-check 标记——键必须是字面量。

data-i18n 机制

<span data-i18n="myPlugin.run" data-i18n-fallback="运行">运行</span>
  • 命中的元素被写 textContent（不是 innerHTML）——标记里别放 HTML；
  • 插件 HTML 是打开时才注入的，内核挂了 MutationObserver：新节点带 data-i18n 就地翻译； 自己动态插的片段若 observer 还没跑，直接 i18n.applyTranslations(node)；
  • 内核只认 data-i18n 与 data-i18n-fallback 两个属性：data-i18n-placeholder / data-i18n-title 没有任何代码读（notepad 里是它自己补的一轮翻译，抄了那段才有用；访达里的同名牌是死标记）。 JS 拼出来的文案走 t(key, fallback)。
