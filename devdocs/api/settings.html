设置中枢 __settings

全系统唯一的设置读写入口。你注册的设置项会自动出现在「系统设置」界面里，不用自己画设置面板。源码：src/javascripts/settings.js。

这是什么 / 为什么用它

每个插件都想存点自己的配置。如果各写各的 localStorage，键名会打架、系统设置界面也管不到你。 中枢的规矩是：所有设置都经过 window.__settings 读写，键形如 owner.key（如 dock.size、myPlugin.enabled）， 存进哪个 localStorage 槽由 owner 派生，你不用关心——但不要绕过它手写第三个 localStorage 键。

方法清单

方法说明
define(def) / defineMany(list)注册设置项（类型、默认值、界面呈现），注册后系统设置面板自动出现控件
get(key, fallback?)读值（带类型解码与缓存）
set(key, value, opts?)写值，返回信封（见下节）
reset(key)恢复默认值
isDefault(key)当前值是否等于默认值
list(scope?)列出已注册项
on(key, fn)订阅单个键的变化，返回退订函数
subscribe(fn)订阅全部变化（fn 收 {key, value, …}）
snapshot(scope?)导出已注册项的原始存储文本（备份/诊断用）

四种类型与校验规则

type行为要点
boolean落盘 "on"/"off"（owner 模块的既有读法决定的形态）；读回时 on/true/1、off/false/0 都认。未注册的裸键例外：写 "true"/"false" 读回还原成布尔。想让系统认出你的键，就先 define。
number配 min/max/step：超界不拒绝，而是钳到边界再按 step 取整，返回钳后的值。
string可配 values 候选白名单：写入不在候选内的值直接拒绝（reason 形如「取值 neon 不在候选值 light / dark / auto 内」）。
json接受对象或 JSON 文本；坏文本被拒；对象默认值与存储值浅合并（新版新增字段自动带默认值）。

set() 返回信封：三种「失败」要分开处理

const r = __settings.set("myPlugin.opacity", 2);
// r = { ok, key, value, persisted, changed, reason? }
字段含义
ok是否通过校验；false 时 value 是当前值（不是你传的）
value校验/钳制后真正生效的值（比如传 2 被钳到 1）
persisted是否写进 localStorage；false = 本次会话能用，刷新回退
changed是否与旧值不同；同值写入不广播、不记日志
reason仅拒绝时出现（中文说明，同时进 __log 的 error）

define：让设置项出现在系统设置里

__settings.defineMany([
  { key: "myPlugin.enabled", type: "boolean", default: true, owner: "myPlugin", pane: "plugins",
    label: "启用我的插件", hint: "关闭后不再注入任何界面", control: "switch", group: "我的插件", order: 10 },
  { key: "myPlugin.opacity", type: "number", default: 0.8, min: 0.2, max: 1, step: 0.05,
    owner: "myPlugin", pane: "plugins", label: "浮层不透明度", control: "slider",
    format: "fixed1", group: "我的插件", order: 20 },
]);
  • pane: "plugins" 把设置项归到「系统设置 › 插件」面板：收录规则 = owner 不是 system、pane 缺省或为 plugins、没被 hidden。 每行控件由系统按 control 自动生成（switch / slider / segmented / …）。
  • 三条生命周期约束： ① 在插件初始化时就 define（定义了才出现在设置界面）； ② define 必须可重复调用——入口脚本每次打开都重跑，同名定义做字段合并，天然幂等；所以别在 apply 闭包里捕获外部状态； ③ 没有「撤销定义」接口——卸载后定义仍留在表里。想「关掉即隐藏」就用 hidden 字段，或在 apply 里兜住缺失状态。

event 与 apply：二选一，别都写

写法行为什么时候用
apply: (v, {previous, persisted, source}) => {}落盘后由中枢调用；抛错只记 error 不打断写入owner 自己把值应用到真实状态（推荐）
event: "my-change"中枢在 window 上补发一个 CustomEvent，detail 是序列化字符串（json 类型例外，给对象）只有监听没有 setter 的历史模块（dock 7 项 / 启动台 2 项 / Siri 1 项）
同一个定义里两个都写会派发两遍（owner 的 apply 里往往自己 dispatchEvent，中枢再补发一次，监听方执行两遍）。 新插件两个都不必写：需要即时生效就订阅 settings-changed。

订阅变更（三种姿势）

// 1) 单键订阅（最常用）
const off = __settings.on("myPlugin.opacity", (value, detail) => repaint(value));
// 2) 全量订阅
const off2 = __settings.subscribe(d => { if (d.key.startsWith("myPlugin.")) repaint(); });
// 3) document 统一事件：detail = {key, value, previous, persisted, type}
document.addEventListener("settings-changed", onChanged);
  • 同值写入不广播（别拿它当心跳）；批量恢复（opts.silent）也不广播。
  • 必须在 plugin-unload 里退订——入口脚本每次打开都重跑，旧订阅连同捕获的已卸载 DOM 会永久累积（内存泄漏 + 重复执行）。

别把密钥放进设置

snapshot() 会把已注册项的原始存储文本整份导出；settings-changed 的 detail 和 __log 的写入记录同样带值。 所以口令类数据要存设置中枢之外的自有槽，且只存哈希。仓库示范（lock.js 锁屏口令）： SHA-256(盐:口令) 才落盘，日志里既无明文也无摘要。
