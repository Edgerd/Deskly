## 0. 现在不能动

宣传片正在另一个会话里用无头浏览器录制界面，任何路径变动都会让已录素材作废。本节是执行的硬前置条件，先读这里再读其余章节。

**冻结范围（录制期间一律不许动）**

| 对象 | 为什么 |
|---|---|
| `index.html`、`manifest.json`、`sw.js` | 录制脚本按 URL 抓界面；这三个是运行时入口，改了就换页面 |
| `src/`、`assets/`、`mods/` 下的任何文件名与目录名 | 浏览器按这些 URL 请求资源，改名即 404，画面直接缺图/缺样式 |
| `assets/icons/`、`assets/svgs/` | 另一个会话正在做图标 WebP 化与清理（6452 个删除未提交），此时再动会与它的中间态互相覆盖 |
| `2026-11-06/promo-video/` | 素材工作区（实测 4218 个文件、约 1.31 GB），只读 |

**可以做的事（不会影响录制）**

- 读文件、跑只读统计脚本、写 `reports/plan/` 下的文档。
- 跑 `npm run check` 这类只读校验（不写运行时资源）。

**可以开始执行的判据**

1. 录制方明确回复「进程已退出、素材已导出归档」；
2. `2026-11-06/promo-video/` 目录不再有新写入（观察 1 分钟 mtime 无变化）；
3. 开工前先跑一次 `npm run check` 并记录通过基线，作为后续每批的对照。

三条同时满足才进入第 5 节的批次 A。**批次 A 之前不要动 `assets/svgs/`**——虽然它零引用，但删除会触发工作区大范围变更，录制中断时不易回退到干净状态。

## 1. 现状诊断

先给结论：这套目录的问题不是"没有分层"，而是**分层标准不统一**——同一个维度上同时存在三套规则：运行时/开发期/产物没有分开（`assets/` 里既装运行时资源也装生成物和原始素材）、文档有三个同义目录（`docs`/`devdocs`/`dev/devdoc`）、代码按"技术类型"和"业务域"混着切（`src/javascripts` 顶层 50 个文件平铺，同时又有 `wm/`、`ui/`、`core/` 等 5 个按域切好的子目录）。

### 1.1 运行时 / 开发 / 产物混在一起

## 2. 目标结构

分界线只有一条：**浏览器会按 URL 去请求的，留在能被请求的位置；只有人和开发脚本会读的，挪出去。** 判据是"这个文件会不会被 `<script>`/`<link>`/`import`/`fetch`/`url()` 命中"，不是"它长得像资源还是像代码"。

```
StartOS/
├── manifest.json                       # 运行时入口：4 个图标路径 + service_worker + newtab
├── index.html                          # 运行时入口：44 条 script/link 引用
├── sw.js                               # 运行时入口：按首段 "mods" 分派（见 4.4）
├── package.json                        # 只聚合 dev 校验脚本（13 条 script）
├── README.md / README.zh-CN.md
├── LICENSE / .gitignore
│
├── src/javascripts/                    # 运行时代码（只被 import）
│   ├── boot/       入口与启动链：能"被执行"的最外层
│   ├── kernel/     内核服务：API、插件、设置、日志、权限
│   ├── shell/      桌面外壳：桌面/顶栏/程序坞/控制中心/锁屏等系统 UI
│   ├── wm/         窗口系统（原样保留）
│   ├── ui/         通用 UI 组件（原样保留）
│   ├── core/       文件菜单/打开方式/快速查看等跨插件能力（原样保留）
│   ├── fs/         虚拟文件系统（原样保留）
│   └── dock/       程序坞拖拽与菜单（原样保留）
│
├── assets/                             # 运行时资源（只保留会被 URL 请求的）
│   ├── brand/      图标与品牌位图（manifest 图标、favicon）
│   ├── icons/      应用与文件图标（55 个：39 根 + dock 1 + folder 7 + trash 8，22 处引用）
│   ├── images/     界面字形 SVG + 壁纸 + 通用图
│   ├── stylesheets/  css + 同名 scss（11 对，mtime 门禁）
│   ├── fonts/ cursors/ devices/ sounds/ locales/
│   ├── templates/  空文档模板（desktop.js fetch）
│   ├── vendor/     jszip（运行时按需 + 打包脚本共用）
│   └── ui/phosphor/  图标生成器输入（非运行时，见第 6 节保留理由）
│
├── mods/<id>/                          # 14 个内置插件，目录名 = 插件 id，结构不动
│
├── docs/                               # 人读文档与资料（非运行时）
│   ├── dev/        开发文档 Markdown（由 dev/devdoc/ 迁入）
│   ├── reference/  外部知识库（手册构建输入）
│   ├── images/     README 用图
│   ├── promo/      宣传素材
│   ├── reviews/    设计审查与对照稿
│   └── archive/    过期版本
│
├── devdocs/                            # 已发布 HTML 文档站（原位，门禁绑定）
│
├── reports/                            # 审查与方案产物
│   ├── audit/  fidelity/  plan/  release/
│
├── dev/                                # 只在开发机跑，运行时永不加载
│   ├── checks/      19 个一致性/回归检查
│   ├── probes/      4 个安全与行为探针
│   ├── generators/  手册内容、空模板、图标表生成器
│   ├── tools/       打包、基准、一次性度量
│   └── fixtures/    探针用的临时夹具（若需要）
│
└── .github/             CI 打包（scripts/pack-crx.mjs + workflows）
```

目标结构里"运行时可加载的"只有 5 个位置：`manifest.json`+`index.html`+`sw.js` 三个根文件、`src/`、`assets/`、`mods/`。其余全部是开发期或人读资产——这就是判断某个文件该往哪放的唯一标准。

### 4.4 `sw.js`：没有缓存清单，只有一处路径分派

`sw.js` **不是** precache 型 Service Worker，没有 `CACHE_FILES` 之类的清单，因此不存在"缓存清单条目要跟着改"的问题。它的风险集中在一处：

```js
// sw.js:28-29
const parts = url.pathname.split("/").filter(Boolean);
if (parts[0] !== "mods") return;   // 只认 URL 首段是 mods
const id = parts[1];               // 第二段当插件 id
```

含义：
- `mods/` 必须是**站点根目录**下的一级目录，且 `mods/<id>/<file>` 三段结构不能变。改名为 `plugins/`、或嵌到 `src/mods/` 都会让 ZIP 安装的插件全部 404（`installedIds` 永远不命中，全部透传网络）。
- 同类假设在 `src/javascripts/caller-context.js` 的 `MODS_FRAME`、`src/javascripts/paths.js` 的 `modDir`（`./mods/${id}/`）里各有一份，`dev/static-check.mjs:73` 的 `["assets/","mods/","src/"]` 切片列表是第四份。

## 5. 分批顺序

分批依据是"断点半径"：一批只碰一类引用，出问题能用一次 `git diff` 看全。每批结束都必须 `npm run check` 全绿才算完成。

### 批次 A：基线（不挪任何文件）

1. 记录 `npm run check` 输出与退出码；
2. 对 `index.html`、`manifest.json`、`sw.js` 记 sha256；
3. 在 `reports/plan/` 建执行清单（勾选式）。

产出：可对照的基线。风险 0。

### 批次 B：清零引用与空目录（最小风险）

- 删空目录 `assets/svgs/`、`assets/apps/`；删 `assets/ui/index.css`、`index.scss` 与 16 个 `assets/ui/*.svg`；删 `dev/__pycache__/`。
- 附带去 `paths.js:73-75` 三个 `legacyApp*` 死函数与 `window.js` 里对应用法（若确认无调用）。
- 前置：先确认并发会话的 WebP 化已停止并提交——`assets/icons` 当前 55 个文件里仍有 PNG/WebP 并存（如 `Messages.png` 与 `Messages.webp`），它落定前不要动这个目录。
- 验证：`npm run check` 全绿；`git diff --stat` 只应有删除；再跑一次全仓 grep 确认 0 引用。
- 为什么排第一：不改变任何被请求的 URL，浏览器侧零风险。原 6286 个 SVG（14.6 MB）已被并发会话清空，本批只剩 18 个死资源与 2 个空目录。

### 批次 C：文档收口（无运行影响）

- `dev/devdoc/*.md` → `docs/dev/`；`docs` 下 6 篇 → `docs/reviews/`；旧版 → `docs/archive/`；知识库 → `docs/reference/`。

- 验证：`npm run check`（重点是 `changelog-check` 仍能读到 `docs/changelog.json`、`build-manual-content` 不因路径报错——后者只跑不带 `--apply` 的干跑）。
- 为什么排第二：不碰运行时，但会碰一个生成器输入，所以放在删除之后、脚本搬迁之前。

### 批次 D：`dev/` 四分（只影响开发机）

- 19 检查 / 4 探针 / 4 生成器 / 5 工具 → 4 个子目录。

- 为什么独立成批：174 处硬编码里绝大多数在这批，单独成批才能一眼看出是"脚本搬家"造成的回归。
