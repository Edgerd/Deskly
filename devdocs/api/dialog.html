系统弹窗 dialog

全项目唯一的弹窗实现。渲染在 src/javascripts/ui/dialog.js，焦点、按键与取消值的判定在 src/javascripts/ui/dialog-model.js；内核与插件共用同一份，旧的 window.__dialog 只是指向它的薄门面。

三个入口

入口位置包含的方法
Deskly.ui.dialogos-api.jsalert / error / confirm / prompt / choose / progress。插件用它，没有 permission
window.__dialogui/alert.js旧门面：alert / error / confirm / messageBox / prompt。保留是为了不改动既有调用点的位置参数签名
dialog（ES 模块）ui/dialog.js全部方法（含 permission）。内核模块与 api-grants.js 用它

三者背后是同一份实现，不存在第二套弹窗。新代码优先用 Deskly.ui.dialog（对象形式、参数自解释）；维护老代码时可继续走 window.__dialog。

方法签名与返回值

方法参数返回
alert({title, message, okText, icon, html})单按钮提示Promise<"ok">
error({title, message, okText, icon, html})单按钮错误，按钮用红色Promise<"ok">
confirm({title, message, confirmText, cancelText, danger, icon, html})确认 / 取消两项Promise<boolean>
prompt({title, message, value, placeholder, password, confirmText, cancelText})一个文本输入框Promise<string|null>
choose({title, message, buttons, dismissValue, …})任意按钮表；buttons 项为 {label, value, style}Promise<任意按钮值>
permission({appId, appName, permission, label, description, consequence, icon})权限授权，仅内核可调Promise<"deny"|"once"|"always">
progress({title, message})不确定进度控制器 {update, close, fail}

message 默认按纯文本渲染（换行转 <br>），只有传 html: true 才当 HTML 解析。插件文案一律走纯文本，别为了排版打开 html。

取消约定：任何时候都有明确返回值

方法确认取消（Esc / 点遮罩）
confirmtruefalse
prompt输入的字符串null
permission"once" / "always""deny"
choose所点按钮的 value调用方传入的 dismissValue
alert / error"ok"同样 "ok"（单按钮没有取消态）

这两条路径走同一个取消值，不会出现 undefined：

  • 按 Esc；
  • 点遮罩本身（只判 target === 遮罩，点弹窗内部不算）。

choose 的 dismissValue 建议显式给（false / "cancel" / null）；缺省值是 null。

键盘与焦点

操作行为
Esc取取消值。进度弹窗不允许取消，按 Esc 无反应
Tab / Shift+Tab在按钮与输入框之间循环，不跑出弹窗
Enter执行当前焦点项；没有焦点时落到默认项
初始焦点普通弹窗在主按钮；输入弹窗在输入框（并全选）；danger 弹窗在安全项
关闭后焦点回到触发弹窗的元素

弹窗可以叠加：新弹窗压在旧弹窗之上，只有栈顶那一层处理键盘，底下那层保持打开，等它自己的 Promise 被处理。

danger：危险操作把焦点放在安全项

删除、覆盖、清空、重置、强制退出这类不可逆操作传 danger: true，会同时改变两件事：

  • 确认按钮改用 destructive 样式，视觉权重与后果一致；
  • 初始焦点落在「取消」，所以直接按 Enter 只会取消，不会误删。
const ok = await Deskly.ui.dialog.confirm({
    title: "「草稿.md」将立即删除，不经过废纸篓，无法撤销。",
    message: "删除后无法恢复。",
    confirmText: "删除",
    danger: true,
});
if (!ok) return;

内核里已接线的位置：桌面删除与废纸篓、清倒废纸篓、强制退出、卸载与覆盖安装、清除历史、替换与清除登录密码、清除本地数据、恢复默认设置、删除相簿与永久删除照片、Office 未保存更改。

权限请求只能由内核发起

permission() 的返回值是 "deny" / "once" / "always"，按钮固定为「拒绝 / 仅此一次 / 始终允许」。它不是普通弹窗，插件不能自己弹：

  • Deskly.ui.dialog 上没有 permission；window.__dialog 上也没有；
  • 插件即使直接 import 该函数，调用栈里出现 mods/<id>/ 帧就按 "deny" 返回并记一条 warn；
  • 授权框由 api-grants.js 在敏感能力首次被调用时发起。
为什么 如果插件能自弹授权框，它就能造出一枚系统样式的「始终允许」，账本随即失去意义。声明能力请写 manifest.permissions，运行期交给系统询问。

进度提示

const p = Deskly.ui.dialog.progress({ title: "正在导出", message: "准备文件…" });
p.update({ message: "写入第 2 个文件…" });
p.close();                       // 正常收尾
// p.fail("导出失败：磁盘空间不足"); // 把说明换成失败原因，再由调用方 close()

进度弹窗没有按钮、不可 Esc、不可点遮罩关闭，只有调用方能收尾。默认条为不确定进度动画，只动 transform。

从旧写法迁移

旧写法改法
window.alert("标题")await Deskly.ui.dialog.alert({ title, message })
window.confirm("…")await Deskly.ui.dialog.confirm({ title, message })——返回 boolean
window.prompt("…")await Deskly.ui.dialog.prompt({ title, message, value })——返回 string|null
__dialog.messageBox({…})await Deskly.ui.dialog.choose({ buttons, dismissValue })
插件自造的遮罩 + 浮层换成上面任一入口，别再做第二套弹窗

不要直接调用浏览器原生的 alert / confirm / prompt：样式与宿主不一致，而且会阻塞整页脚本。

视觉与动效

外壳沿用宿主提供的 swift-messagebox（毛玻璃与圆角），遮罩与进度条样式由 ui/dialog.js 自行注入，不改共享样式表。过渡只用 opacity 与 transform，缓动 cubic-bezier(.32,.72,0,1)；html[data-reduce-motion="on"] 下关闭过渡与进度动画。层级取 zindex.js 的 Z.MODAL（遮罩）与 Z.MODAL + 1（弹窗本体），界面不使用 emoji。
