废纸篓闭环 trash.js

v0.2.95 新增内核：/废纸篓 的唯一读写入口。OSFS.remove 在 UI 侧只经这里收口。

为什么有它

旧版唯一的删除路径是 OSFS.remove 硬删——「删了就找不回」。闭环后： 拖/移文件进废纸篓 → 图标变满 → 访达可见 → 「放回原处」可撤销 → 「清倒」弹确认且真删。

模块与事件

import { moveToTrash, putBack, dropFileToTrash, emptyTrash,
         isTrashNotEmpty, TRASH_ORIGIN_SUFFIX } from "./trash.js";
// 或全局：globalThis.__trash（模块顶层自挂）

document.addEventListener("trash-changed", (e) => {
  e.detail.empty;   // 是否已空（图标满/空态、界面刷新都看它）
});

API

函数语义返回
moveToTrash(srcPath)OSFS.move 进 /废纸篓（唯一名顺延 a (1).txt，不覆盖）+ 写溯源伴生 <名>.deskly-origin（JSON {originalPath, movedAt}）{ok, path?, reason?}； reason: "notfound"（源不存在）/ "error"；NeedsReauthError 原样抛出
putBack(trashPath)读伴生还原原路径；原目录没了（被清倒过）落 /文档； 没有伴生的条目（拖入的原生文件）返回 noorigin，调用方保持「放回原处」禁用——不编造原路径{ok, path?, reason?}
dropFileToTrash(file)程序坞拖入分支：原生 File 直接写进 /废纸篓（无溯源）{ok, path?}
emptyTrash()逐条递归移除（目录 {recursive:true}）+ 清伴生{ok, removed}
isTrashNotEmpty()满/空判定（伴生文件不算内容）boolean

三条入口（已接通，勿再造）

入口行为
桌面拖入文件 / 新建文件夹时内容落 /桌面（同名顺延不覆盖，改名同步记录）； 右键「移到废纸篓」= moveToTrash；遗留无记录的图标保持旧行为（移除 DOM），不假装进过废纸篓
访达右键「删除」（文件入口 v0.2.95 补齐）= 移入废纸篓；/废纸篓 内给「放回原处」（有伴生才启用） + 空白处右键「清倒废纸篓...」（带确认）；视图自动过滤 .deskly-origin 伴生（记账文件，不是真实体）
程序坞拖 OS 文件进废纸篓 = dropFileToTrash；点击废纸篓 = 打开访达并导航到 /废纸篓 （「前往」菜单也有该项）；图标满/空由 trash-changed 驱动（「常规」变体自动切同色族「装满」版， 显式黑白/透明变体不动，见 trashIcon.getTrashIconForFullness）

开发者规则

  • UI 侧删除统一走 moveToTrash / emptyTrash，不再直接 OSFS.remove（顶层夹内容除外）；
  • 伴生后缀常量 TRASH_ORIGIN_SUFFIX（".deskly-origin"）——你渲染 /废纸篓 列表时用它过滤；
  • NeedsReauthError 不要吞：权限未批时图标态保持现值、界面如实提示重新授权（别假装「是空的」）；
  • 磁盘后端下伴生文件会在用户真实文件夹里可见（xxx.deskly-origin）——设计内行为，命名带 deskly 前缀便于识别。
