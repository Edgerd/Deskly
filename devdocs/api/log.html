日志 __log

可查、可留存、可导出的运行记录。你的 console.* 早就被自动归档了——但显式用 __log，才能按来源分类、按级别过滤。源码：src/javascripts/log.js。

这是什么

桌面里有十几个插件和几十个内核模块同时跑，出了问题只看 console 根本分不清是谁打的。 __log 把每条日志挂上「级别 + 来源」存进内核缓冲（跨窗口、跨刷新留存），在顶栏「调试 → 查看运行记录」里可以按来源/级别筛选、导出、复制。 log.js 求值时会给原生 console.* 包一层——先归档再原样输出，所以旧代码不用改造，浏览器控制台行为完全不变。

方法清单

方法说明
info(source, msg, data?) / warn / error / debug按级别写一条；被门槛滤掉时返回 null
entry(level, source, msg, data?)级别是变量时的统一入口；非法级别按 info 归档
for(source)返回绑定来源的子日志器（.info/.warn/.error/.debug/.entry/.timer）
timer(label)__log.timer("首屏").stop() 以 info 记毫秒差并返回数字
assert(cond, source, msg)条件不成立记 error 并返回 false
query(opts?) / recent(n=100) / count() / stats()条件筛选 / 最近 n 条（时间正序）/ 总条数 / 分级分来源统计（含 capacity 与 dropped）

门槛与来源分类（两个最容易误会的行为）

  • 默认门槛是 info：你写的 debug(...) 不出现，是门槛滤掉的，不是丢了。 排查时先 __settings.set("debug.logLevel","debug")。 相关六个设置项由 log.js 自注册：debug.logLevel（门槛）/ debug.bufferSize / debug.persist / debug.captureConsole / debug.captureErrors / debug.persistCount。
  • 来源统一带类别前缀：已经含斜杠的照用（如 kernel/dock）；裸名按内核模块白名单判定，未命中一律归 plugin/。 所以插件要显式写 plugin/<你的id>——哪天内核加了同名模块，你的日志会静默跑进 kernel/ 里，「按程序分类」维度就废了。

推荐写法

const log = window.__log.for("plugin/my-plugin");
log.info("界面就绪");
log.warn("配置缺失，使用默认值", { key: "opacity" });
log.timer("首屏").stop();          // → info 级别记录耗时毫秒数

在哪里看

顶栏「调试 → 查看运行记录」：清空 / 导出文件 / 复制剪贴板 / 切换门槛 / 重载当前插件都在那个菜单里。 「调试」菜单本身由 debug.developerMode 设置项门控（只控制菜单显隐，不影响日志系统本身）。
