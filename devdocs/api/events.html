事件与全局接口

桌面里的 CustomEvent 地图 + window.__* 全局钩子速查 + 菜单 cmd 语法。

插件生命周期事件（window）

事件detail谁发
plugins-ready—plugin-manager 注册表就绪（14 内置 + ZIP 还原）
plugin-registered{id, manifest}每个插件注册时（api-grants 的 grantAll 走这里）
plugin-app-load{id, appId, windowName, el}多应用插件：每个应用窗口就绪（外壳只注一次）
plugin-app-open{id, appId, windowName, file}访达带文件打开（窗口复用也发）
plugin-app-unload{id, appId}关掉其中一个应用窗口
plugin-unload{id}整个插件无存活窗口；你的全局监听 / 定时器 / __ 钩子都在这里释放

状态广播（document，detail = 对象，bubbles: true）

事件detail语义
settings-changed{key, value, previous, persisted, type}设置中枢写入（同值不广播）
languagechange—语言切换（i18n.onChange 的底层事件）
trash-changed{empty}废纸篓增删成功（v0.2.95，驱动 Dock 满/空图标）
trash-icon-change变体键用户切废纸篓图标变体
deskly:* / 自定义 topic任意经 Deskly.bus.emit(topic, data) 或内核 app-registry.broadcast()（形状相同：document + bubbles + CustomEvent.detail）

window.__* 全局钩子速查（真实存在，逐条有 file:line）

钩子能力
__dialog系统弹窗：alert / error / confirm(→Promise<boolean>) / messageBox / prompt（替代原生）
__notify站内通知：show(opts) 返回元素或 null、dismissAll()、pendingCount()、resetPendingCount()
__popover下拉浮层：open({anchor, content, …}) 把菜单搬进 body 浮出层（能伸出插件窗口）、close / closeAll / openCount / z
__dock程序坞：minimizeToDock / restoreFromDock / setBadge / addToDock / updateRecents / syncRunningApps …
__settings / __log见 设置 / 日志
__sound / __display / __lock / __permissions / __spotlight各自 owner 模块接口
__surface模糊等级与文字令牌，见 表面
__osfs文件存储，见 OSFS
__launchpad启动台开/关（isOpen / open / close）
__getPluginByName / __getAppByName / __pluginManagerReady按显示名解析插件/应用记录、等注册表就绪
__menuActions菜单命令注册表（你加的键必须在 plugin-unload 里 delete）

菜单 cmd 语法（字符串形态只有两种合法）

name                 // 注册表键名
name('arg')          // + 至多一个字符串实参

其它任何 JS 表达式一律被拒绝并打日志——MV3 扩展页 CSP 是 script-src 'self'， new Function / eval 直接失败。JS 里写的菜单表可以把 cmd 放成函数（内核内置 mod 这么用）， 但 HTML 上的 cmd="…" 属性读出来永远是字符串，插件界面只能写键名。
