架构总览

执行模型、数据流与「版本与更新」规则。写任何代码之前先读这页。

执行模型（最重要的两条）

  1. 没有 iframe。 mod 由 plugin-manager.js fetch 三件资源后注入宿主主文档： HTML 片段 insertAdjacentHTML 进 body，脚本是全新 URL 的 <script type="module">。 所以 mod 共享整个桌面 DOM，也共享全部 window.__* 钩子。
  2. 冷加载。 启动只 fetch 14 份 manifest.json（带 ?v=VERSION）建立注册表， 派发 plugins-ready；点击应用时才拉 style/html/script。详见 冷加载机制。

版本与更新（?v= 三处规则）

位置写法原因
manifest.json fetch（冷加载注册）?v=VERSION随发布自动失效缓存
index.html 里宿主资源（script/css）?v=VERSION同上；版本升级时整站资源一起失效
mod 的 style.css / index.html / 插件 manifest内置 ?v=VERSION；ZIP 安装 Date.now()ZIP 可被同 id 覆盖安装，必须每次取新
红线 ES module 的 import 说明符永远不带 ?v=：带与不带是两个模块， 核心模块被求值两次 → 两份状态互相覆盖全局钩子（settings / log / 注册表都会分裂）。 宿主资源升级 = 改 version.js 的 VERSION + 全仓 index.html 的 ?v= 串（当前 15 处），见 版本与更新。

「没有 iframe」的两条推论

  • mod 里的 document、window 就是宿主桌面本身：别假设自己独占 DOM（选择器要带 mod 的作用域前缀）； 也别假设 window.location.reload() 有语义——扩展新标签页里它只会重载整个桌面。
  • window.Deskly 是能力门面不是沙箱：mod 直接 import 内核模块（../../src/javascripts/xxx.js） 是允许的（内置 mod 都这么做），第三方 ZIP 插件靠 sw.js 拦截 ./mods/<id>/ 路径拿到同等待遇； 能力边界由 manifest.permissions + api-grants.js 账本约束，见 Deskly。
