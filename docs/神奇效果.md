# 窗口最小化「神奇效果」实现文档

版本：0.3.5  
更新日期：2026-11-02

## 1. 目标与交互

窗口黄色最小化按钮、窗口菜单的最小化命令会将窗口吸入对应 Dock 图标；点击已最小化窗口的 Dock 图标会反向展开。Dock 位于底部、左侧或右侧时使用各自的吸入方向。

动画分为两个阶段：前 40% 在原位捏颈，靠近 Dock 的一侧先收窄；后 60% 整体向 Dock 倾倒，条带按实时到坞线的距离继续收窄，越过坞线后在 26px 内淡出。完整时长为 620ms。

「减少动态效果」开启时仍使用既有缩放淡出，不播放形变。

系统设置 › 桌面与程序坞提供「最小化窗口使用」：

- **神奇效果**（默认）：本文描述的 WebGL Genie 形变；
- **缩放淡出**：不生成快照、不走 Genie，沿用窗口自身的透明度淡出；还原时播放 160ms 的快速轻淡入。

开窗淡入统一提速到 160ms，进入曲线为 `cubic-bezier(0.22, 1, 0.36, 1)`（ease-out），关闭与缩放淡出为 240ms 的 `cubic-bezier(0.4, 0, 1, 1)`（ease-in）。神奇效果还原不会补任何淡入，缩放样式才保留一次 160ms 的轻量淡入。

启动台采用同一组动效语义：整体淡入 240ms、网格 320ms 的 ease-out 缩放落位；关闭 260ms 的 ease-in 后卸载。所有曲线都是非线性缓动，不做弹跳或长尾过冲；减少动态效果开启时取消开关动画并立即关闭。

## 2. 参考模型

几何模型参考：

- daniate《细说如何完美实现 macOS 中的神奇效果》；
- SquarePants1991 的 iOS 仿 Mac 最小化实现与 `SquarePants1991/MagicalTransition`；
- 相关 Metal Shader 的两阶段顶点形变与余弦收口公式。

`react-native-magic-move` 与 `magic-move` 属于共享元素转场方案，不负责 Genie 网格形变，因此只用于研究状态衔接，没有引入其运行时。

真实 `.window` 不写 `transform`、`filter` 或 `clip-path`，避免破坏 `backdrop-filter` 的亚克力效果。所有形变只发生在独立的 `pointer-events:none` 覆盖层上，真实窗口只负责显隐。

## 4. 形变与渲染

条带到 Dock 的实时距离占总行程比例为 `f`，收口宽度比为：

```text
pinchScale(f) = 0.51 - 0.49 * cos(π * f)
```

因此 `f = 1` 时保持原宽，`f = 0` 时约为原宽的 2%。它等价于参考 Shader 中的：

```text
0.5 * 0.98 * cos(π * f + π) + 0.5 + 0.01
```

前 40% 使用 `easeOutCubic` 完成原位捏颈；后 60% 使用 `easeInCubic` 完成倾倒。底部 Dock 把窗口切成水平方向形变，左右 Dock 使用垂直方向。

WebGL2 正常路径只上传一次快照纹理，每帧一次全屏绘制。片元着色器按目标像素反算源坐标：

```text
源位置 = 目标位置 - 刚性倾倒位移
源距比 = 源位置到坞线的距离 / 总行程
横向缩放 = pinchScale(源距比 - 倾倒比例)
源横坐标 = 坞点 + (目标横坐标 - 坞点) / 横向缩放
```

边缘覆盖用 `fwidth` 做 1 个物理像素的抗锯齿，不再依赖离散条带，因此阶梯消失。纹理使用预乘 alpha、线性采样、mipmap 与异向过滤：窗口圆角不会渗出黑边，横向压缩时也不会无谓地模糊纵向文字。

Canvas 2D 只在 WebGL2 或纹理上传失败时启用，条带厚度为 2px、上限 720 条，作为兼容兜底而非主路径。

## 5. 快照与延迟

点击路径不再启动 DOM 序列化。取图顺序为：

1. 800ms 内的新鲜缓存，直接开始动画；
2. `chrome.tabs.captureVisibleTab` 捕获浏览器已合成的标签页，再按窗口矩形裁剪；通常几十毫秒；
3. 尺寸一致但已过期的缓存；
4. 都没有则立即返回，由调用方走缩放淡出。

快照保存的是窗口内局部像素，因此缓存只按宽高判断是否可复用：拖动窗口只改 `x/y`，不会让快照失效；缩放改变尺寸时才作废并重新预热。拖动/缩放结束后会主动刷新一次快照：拖动只刷新原生候选，缩放与吸附动画在几何稳定后重新采集。

窗口在 `revealOpen` 真正可见 280ms 后预热快照；指针进入红绿灯时再刷新一次。原生截图不可用时，snapdom 才在 `requestIdleCallback` 的空闲期生成缓存，参数为 `embedFonts:false`、`noShadows:true`、显式窗口尺寸和 DPR（上限 2）。

这条分界是因为 snapdom 的同步序列化一旦开始，`Promise.race` 的超时也要等主线程让出才能触发，仍会表现为“点击后卡住”。因此它只允许出现在预热路径，绝不进入点击路径。

原生截图裁剪后按窗口 `border-top-left-radius` 做透明遮罩，圆角之外的桌面像素不会跟着形变。原生截图会使用共享的进行中任务，避免悬停刷新与点击取图并发调用截图 API。

旧实现使用的 modern-screenshot 约需 1.1–1.7s，远超前一代 400ms 预算；该依赖已经删除。snapdom 仅保留为无原生截图能力时的可见窗口预热兜底。

覆盖层在隐藏真窗前同步绘制首帧，避免等待第一次 `requestAnimationFrame` 时出现空白帧。还原复用最小化时的 WeakMap 快照，避免先显示真窗再截图造成闪烁。真窗在神奇效果期间经历过 `display:none`，恢复显示会重播 `.window` 的 `window-fade-in`；因此 Dock 揭示时会先加 `wm-shown` 关闭该入场动画，落点之后直接显示真实窗口，不再补一段淡入。

## 6. 失败与竞态处理

以下情况直接走既有缩放淡出或直接显示：

- 减少动态效果开启；
- Dock 图标不存在或几何行程不成立；
- 没有新鲜缓存、原生截图失败且没有旧缓存；
- WebGL2 不可用时退回 Canvas 2D；两种渲染器都失败才回退缩放淡出；
- 没有可用于还原的缓存快照。

快照期间如果用户已还原或关闭窗口，不再接管显隐。动画期间状态被反转会立即拆除覆盖层。还原无论动画成功、失败还是中止都会执行 reveal；如果期间再次最小化，reveal 的状态守卫不会错误揭开窗口。

## 8. 已知边界

- 动画使用窗口静态快照，播放期间窗口内部的视频、Canvas 或实时内容不会继续变化；动画结束后真窗立即接管。
- 原生截图是机会性能力：如果扩展页无法调用 `captureVisibleTab`，会改用 snapdom 预热，首次点击可能在缓存尚未生成时走缩放淡出。
- 原生截图只应裁取当前最上层窗口；中心点被其他浮层覆盖时会放弃原生路径，避免把别的界面吸进 Dock。
- 快照只代表采集时的窗口尺寸与内容；窗口移动、缩放或内容大幅刷新后，点击时会优先尝试新的原生截图。
- 非标准跨域资源能否进入 snapdom 快照取决于浏览器与资源响应；失败时保留缩放淡出兜底。
- 这是按参考模型复刻的 Genie 动画，不声称与 macOS 私有实现逐像素一致。
