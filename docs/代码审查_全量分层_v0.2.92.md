## 一、总体评估

**一句话结论**：存储内核（`osfs.js`）与 MV3 合规面是这一轮里质量最高的两层——单一根目录 + 双后端、路径规范化、跨标签页通知、事务边界都写得比多数同类项目严谨；**真正的风险集中在"同意机制"的边界上**：账本、不可逆擦除动作、调用者识别三者都以"同 realm 都可访问"的方式暴露，其中两处是纯代码问题（应当收窄），第三处是已自述的缺口但从未被复现确认。

| 严重度 | 数量 |
|---|---|
| P0（崩溃 / 数据丢失 / 权限绕过 / 新标签白屏） | **0** |
| P1（功能错误 / 特定场景不可用 / 可自授权 / 不可逆动作无闸门） | **4** |
| P2（体验 / 性能 / 兼容 / 信息泄露 / 潜在挂死） | **9** |
| P3（代码质量 / 可维护） | **2** |

**风险集中区域**

1. **权限账本的写入口暴露为全局**（`api-grants.js:462`）：`grantAll` / `activate` / `clearGrants` 都挂在 `globalThis.__grants` 上，插件可自我提权。
2. **不可逆动作没有 UI 闸门**（`permissions.js:258`）：`resetAll` 的"确认"只是一个函数参数，同 realm 一行调用即可清空用户全部文件。
3. **调用者识别 fail-open**（`os-api.js:57`）：`caller === null` 时直接放行，而 null 的判据来自调用栈解析。
4. **书签路径用标题拼段**（`vfs.js:52`）：标题含 `/` 即整条导航链错位。

```js
 * 内核侧在调用插件回调前显式声明的归属。
 * 为什么需要它：`guard()` 靠解析调用栈认插件，而栈解析失败时会回落成 null = 内核 = 放行。
 * 事件回调是这条回落路径最常被踩中的地方（回调由内核派发，内层帧不一定带 mods/ 前缀）。
 * 用一个模块内变量在派发期间声明归属，插件无法从 window 上改写（它只能 import 到这个
 * setter，那属于主动绕过，与文档里写明的威胁模型同级）。
 */
let ambientCaller = null;

/** 在指定归属下同步执行 fn；嵌套调用恢复上一层。 */
function withCaller(pluginId, fn) {
    const prev = ambientCaller;
    ambientCaller = pluginId || null;
    try { return fn(); } finally { ambientCaller = prev; }
}
```

`resolveCaller`（`:201-206`）替换为：

```js
function resolveCaller(hint) {
    if (ambientCaller) return ambientCaller;
    const fromStack = getCallerPluginId();
    if (fromStack) return fromStack;
    if (hint && ledger.has(hint)) return hint;
    return null;
}
```

并把 `withCaller` 加进末尾的 `export { ... }`。

**3b. `src/javascripts/os-api.js`**：import 行（`:38-41`）补 `withCaller`，`bus.on`（`:204-210`）替换为：

```js
    /** 订阅，返回退订函数。插件必须在 plugin-unload 里调用，否则监听器永久累积。 */
    on(topic, handler) {
        const { type, onWindow } = busTopic(topic);
        const target = onWindow ? window : document;
        // 归属在**订阅时**定一次：回调由内核派发，派发期的调用栈不保证还认得出是谁注册的。
        const owner = resolveCaller(window.__currentPluginId);
        const wrapped = (event) => withCaller(owner, () => handler(event.detail, event));
        target.addEventListener(type, wrapped);
        return () => target.removeEventListener(type, wrapped);
    },
```

**3c. `src/javascripts/os-api.js:57`** 的 fail-open 同时改成 fail-closed：


**现在做**
