## 2. 审查方法与判断依据

机械扫描（PowerShell + ripgrep 正则）+ 逐文件判读：

1. 占位扫描：`TODO/FIXME/XXX/HACK/暂未实现/尚未实现/coming soon/not implemented/占位` 全仓 grep（120 命中逐条判读，多数为注释里正常用词，仅下列条目成立）。
2. 空函数/假实现：`action: () => {}`、空函数体、硬编码假数据冒充查询结果。
3. 未接线：291 个导出逐一数全仓引用点；CustomEvent/broadcast 发出方与 addEventListener 监听方双向对照；`settings.define` 键与 `settings.get` 读取点对照；`window.__*` 全局写入点与读取点对照。
4. UI 入口核查：`index.html` 静态菜单 cmd 与 `ui/menuCommands.js` 注册表对接、控制中心 11 模块逐一判真伪。
5. 语言包：4 份 JSON 展平成点分键互相 diff；代码引用键（`i18n.t`/`data-i18n`）与 zh-CN 键集 diff。
6. manifest 审计：13 个 mod 的 permissions 字段与代码真实调用对照。

**判断口径**：「真缺失」= 功能本体不存在且无任何说明；「有意降级」= 浏览器/能力边界导致，代码与 UI 已如实标注；「死代码」= 存在但无读者/无调用。
