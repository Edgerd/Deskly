插件包格式

一个插件包里该有哪些文件、manifest 每个字段谁在读、图标与路径的硬规则、商店自声明怎么写、怎么打成 ZIP。本页所有字段都以代码真实读取方为准。

固定目录结构

mods/my-plugin/
├── manifest.json   # 插件清单（唯一事实来源）
├── index.html      # 界面片段（恰好一个 .window 根元素）
├── style.css       # 样式
├── script.js       # 逻辑（ES Module）
└── icon.png        # 图标（程序坞 / 启动台 / 商店共用）

id 命名：小写蛇形（如 vs_code、system-settings）。合法字符集 [A-Za-z0-9][A-Za-z0-9._-]* 且不含 ..—— id 会被拼进 ./mods/<id>/ 路径和 [data-plugin-id] 选择器，非法即拒绝注册。资源文件名（main/style/script/icon）由 safeAssetName() 校验：只允许单层文件名，防止 ../../x.html 这种跳出插件目录的写法。

manifest 字段全表

「谁在读」一栏告诉你这个字段不写会怎样——有些字段纯粹是给人看的，写了系统也不会用。

字段必填说明谁在读
id✅唯一标识；注册表键 + 资源路径拼接plugin-manager / store-api
name✅显示名（程序坞 / 启动台 / 菜单 / 商店）；多应用套件里也是窗口去重键注册表 + 各界面
entry✅window（窗口应用）| fullscreen（全屏，如启动台）；启动台只列 windowplugin-manager / launchpad
main / style / script 缺省 index.html / style.css / script.jsplugin-manager（经 safeAssetName 校验）
icon 裸文件名；不声明则自动落占位图（见「图标规则」）plugin-manager 图标解析
window.* width / height / resizable / centered 等；被 HTML 里的 data-window 覆盖（后者为准）window-manager
apps[] 多应用插件声明，见下节app-registry / plugin-manager
menus 顶栏菜单自定义：{"文件":[{label, i18nKey?, shortcut?, cmd?, disabled?}]}；只整组替换声明过的菜单标题，未声明的保留系统默认finderbar
version 商店卡片 v<ver> 与安装记账；不做自动更新比对（没有远程源）store-api
type 目前只有 "app" 一种；启动台按它过滤launchpad
description 商店卡片/详情的缺省文案（store.tagline/summary 没写时兜底）store-api
author 根级这个字段没有读取方；商店详情要显示作者请写 store.author无人
store 商店自声明区块，见下节store-api
formats 「能打开哪些扩展名」（[".txt","md"]，带不带点都行）：单应用插件写根级，多应用套件写 apps[].formats——两处内核都会读app-registry / default-apps
permissions✅取值必须来自 22 条权限名（见 Deskly 页）；没声明的能力调用直接 ok:false；用不上也要写 []api-grants（static-check 第 7 节核对）
_installed 商店安装/还原流程写入的内部标记，不要手填store-api

多应用插件（apps[]，参考实现 mods/office/）

一个插件可以提供多个应用（office 套件 = word / excel / ppt 三个）。规则：

  • appId = <插件id>.<app.id>（如 office.word）。
  • 每个应用一个 HTML 片段（缺省 <app.id>.html），片段同样恰好一个 .window 根；宿主把窗口 id 写成 app.windowName || app.name——所以各应用显示名不能互相撞（窗口 id 是去重键）。
  • 外壳只注入一次：首个应用打开时注入 style + script，之后每个应用只注入自己的 HTML 片段。 因此 script.js 顶层只允许登记全局监听与菜单命令，界面初始化必须写在 plugin-app-load 回调里 （detail = {id, appId, windowName, el}）——和单应用「顶层直接 init()」相反，别照搬。
  • 关掉单个应用发 plugin-app-unload；整个插件没有存活窗口时才发 plugin-unload（按 .window[data-plugin-id] 存活数引用计数）。全局资源只在 plugin-unload 里释放。
  • apps[].formats（如 [".docx", ".txt"]，带不带点都行）声明「能打开哪些扩展名」： 访达双击文件时经 getAppByExtension() 找到你 → openApp(appId, {file}) 并派发 plugin-app-open （detail = {id, appId, windowName, file}，窗口已存在也会再派发一次，用来「换文件复用窗口」）。 只有真的实现了 plugin-app-open 的应用才该声明 formats；没命中处理方时访达原样退回 Quick Look。

图标（硬性四条）

  1. 应用图标一律 PNG，禁 SVG（程序坞 / 启动台 / 商店共用位图；菜单栏单色字形不受此限，那是 assets/images 里的 SVG glyph，另一套）。
  2. 新应用图标先到 assets/icons/ 找（含 dock/、folder/ 子目录）。
  3. 找到就复制进插件目录，manifest 只写裸文件名——ZIP 要求自包含；库里原文件不要移走（dock.js 的 iconMap 按名字兜底引用整个库）。
  4. 没有合适的就不声明 icon：系统自动落占位图 assets/icons/dock/Launcher.png，界面里所有 img.onerror 也回退它。占位图只有这一个出处，别在别处再写死路径。

解析顺序：apps[].icon（多应用时优先）→ manifest.icon → ./mods/<id>/icon.png（目录约定兜底）→ 占位图。 套件里的应用缺图标时显示套件图标，不是占位图。

路径写法（三种场景三种规则）

场景正确写法为什么
ES module 的 import 说明符../../src/javascripts/xxx.js（相对文件自身）模块解析基准是文件位置；永不带 ?v=
CSS 里的 url()url(../../assets/…)（相对样式表自身）同上
JS 运行时 URL（<img src>、fetch()、Notification.icon）用 paths.js：assetPath("icons/x.png")、modFile(id, "x.png") 等，产出站点根相对路径（./assets/…、./mods/<id>/…）运行时 URL 的解析基准是文档（index.html），写 ../../assets/… 只是越过根被浏览器截断回来「碰巧能用」，属于巧合不是契约

paths.js 常用导出：assetPath(rel)、assetIcon(name)（icons/ 下 PNG）、glyph(name)（images/ 下 SVG 字形）、 modDir(id)、modFile(id, file)、modUrl(id, file, stamp)、GENERIC_APP_ICON（占位图）。

商店自声明（store 区块）

应用商店的详情页内容不是系统编的，而是你在这个区块里自声明的。写了才渲染，没写的区块不会出现；全部按纯文本处理（不解析 HTML）。

"store": {
  "category": "办公",
  "tagline": "一句话卖点",
  "summary": "长介绍",
  "features": ["能力一", "能力二"],
  "usage": "使用方法",
  "updated": "2026-11-03",
  "author": "你的名字",
  "homepage": "https://example.com",
  "screenshots": ["screens/one.png"]
}
  • 清洗限额（store-api.js 的 storeMeta()）：category ≤24 字、tagline ≤120、summary/usage ≤600、updated ≤20、author ≤60、features ≤12 条且每条 ≤120 字。
  • screenshots 写插件目录内相对路径：只收 png / jpg / jpeg / webp，拒绝含 .. 的路径，最多取前 6 张。截图取不到不算安装失败，但 dev/package-plugin.mjs 打包时会因此拒绝出包。
  • homepage 只收 http(s):// 开头的链接。
  • 权限不写在 store 里：详情页权限栏读的是 manifest.permissions，经 api-grants.describe() 出人类可读文案，与授权账本同源。

打包分发（ZIP）

node dev/package-plugin.mjs <id>      # 产物 dist/<id>-<version>.zip
  • 唯一真源是 mods/<id>/ 目录，ZIP 只是导出物——避免「改了目录却拿旧 ZIP 去装」的分裂。
  • 包内 manifest.json 必须在包根或同一顶层目录下（commonRoot() 判公共根）；包内条目一律 POSIX / 分隔符 （不要用 Windows 的 Compress-Archive，它的反斜杠条目 Service Worker 命中不了）；解包总字节 ≤ 10MB。
  • 打包即校验：id 必须等于目录名、相对依赖必须落在插件目录内、宿主依赖（../../src/…）必须真实存在。 少打一个文件，运行时只会表现为「窗口开了但空白」——这种问题必须在构建期就断掉。
