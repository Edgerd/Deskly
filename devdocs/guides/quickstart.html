五分钟写第一个插件

目标：做一个能在程序坞里点开、带一个窗口的小插件。全程只要四个文件，不用任何构建工具。模板照抄 mods/about/（最小完整骨架）；想看带计算逻辑的例子看 mods/calculator/。

这是什么

一个 Deskly 插件就是一个文件夹，里面装着「清单 + 界面 + 样式 + 逻辑」。系统启动时只读清单（冷加载），用户点击图标时才把你的界面和脚本注入桌面。所以你的代码是「被点活」的，不是常驻的。

五步跑通

  1. 建目录 mods/my-plugin/，放四个文件：manifest.json、index.html、style.css、script.js（图标规则见第 4 步）。
  2. 注册 id：把 "my-plugin" 加进 src/javascripts/plugin-manager.js 的 BUILTIN_IDS 数组（只有内置插件需要这步；走商店 ZIP 分发的不用）。
  3. 刷新看效果：重载扩展，打开新标签页，程序坞里出现你的图标，点击开窗。
  4. 跑自检：node dev/static-check.mjs——manifest 声明的文件在不在、权限名写没写对、资源引用 404 不 404，一次全查。
  5. 验证卸载干净：顶栏「调试 → 重载当前插件」，如果你的界面叠了两层、菜单项多了一倍，说明 plugin-unload 没清干净（见下文「最容易踩的坑」）。

四个文件怎么写

1. manifest.json（清单，唯一事实来源）

{
  "id": "my-plugin",
  "name": "我的插件",
  "version": "1.0.0",
  "entry": "window",
  "main": "index.html",
  "style": "style.css",
  "script": "script.js",
  "permissions": []
}
  • id 必须和目录名一致，小写蛇形命名（只允许 [A-Za-z0-9][A-Za-z0-9._-]*，不能含 ..）。
  • entry 二选一：window（窗口应用，绝大多数）或 fullscreen（启动台那种全屏）。
  • permissions 必须写，哪怕用不上也要写 []——static-check 第 7 节会核对这个字段。取值只能来自 22 条权限名（见 Deskly 页权限表）。
  • 全字段表见插件包格式。

2. index.html（HTML 片段，不是完整网页）

<div class="my-plugin window" data-window="size:420x560 centered">
  <header class="titlebar" data-titlebar>
    <deskly-traffic-lights class="wintools" placement="titlebar"></deskly-traffic-lights>
    <span>我的插件</span>
  </header>
  <section class="content">
    <p data-i18n="myPlugin.title" data-i18n-fallback="我的插件">我的插件</p>
  </section>
</div>
  • 根元素恰好一个，必须带 .window 类——窗口管理器靠它认窗口。
  • 红绿灯组件 <deskly-traffic-lights> 放在带 data-titlebar 的标题栏里；没有标题栏的内容型界面（看图、写字）用 overlay 悬浮形态。详见窗口红绿灯。
  • data-window 声明窗口尺寸与能力（键名 camelCase / kebab / 全小写都认；表外的会被忽略并在 console 里警告）：
    写法含义
    size:420x560 / min:… / max:…初始 / 最小 / 最大尺寸（宽x高）
    width / height / minWidth / minHeight / maxWidth / maxHeight同上的按字段写法（数字），与 Deskly.windows.configure 字段同名
    resizable:true|false可否拖拽缩放
    minimizable / maximizable是否允许最小化 / 缩放（红绿灯禁用态）
    centered打开时居中
    draggable:true|false标题栏是否可拖动
    fixed / modal / multiWindow固定不可变 / 模态 / 允许多窗口
    role / parent / level / snap / titlebar / trafficLights窗口角色 / 父窗 / 层级 / 吸附 / 标题栏选择器 / 红绿灯形态（字符串）
    dragAxis / resizeAxis限制拖动 / 缩放轴向
    aspectRatio:16:9固定宽高比（也可写数值）
    dragBounds:visible / dragBounds:x,y,w,h拖动边界
    与 manifest.window 冲突时以 data-window 为准（应用是尺寸的权威）。

3. script.js（ES Module，顶层直接初始化）

import { i18n } from '../../src/javascripts/i18n.js';

// 插件自带文案：四语都写是仓库规约（cat = 萌猫语言，中文加「喵」尾）
i18n.registerMessagesAll({
  "zh-CN": { myPlugin: { title: "我的插件" } },
  "en":    { myPlugin: { title: "My Plugin" } },
  "ja-JP": { myPlugin: { title: "マイプラグイン" } },
  "cat":   { myPlugin: { title: "我的插件喵" } },
});

function init() {
  const root = document.querySelector('.window[data-plugin-id="my-plugin"]');
  if (!root) return;
  // …界面逻辑…
}
init();

// ★ 硬约束：顶层注册的全局资源必须在 plugin-unload 里释放
window.addEventListener("plugin-unload", (e) => {
  if (e.detail?.id !== "my-plugin") return;
  // 摘掉你挂的 document/window 监听、清定时器、delete window.__menuActions 里你加的键
});
  • import 路径相对文件自身：插件在 mods/my-plugin/，回内核就是 ../../src/javascripts/…。import 说明符永远不要带 ?v=（带了等于把内核模块再加载一份，全局状态会分裂）。
  • 系统给你的窗口根会自动带 data-plugin-id="你的id"，用它做选择器，别用裸 .window（桌面上全是别的窗口）。

4. style.css

  • 作用域自觉：所有选择器以你的窗口类开头（.my-plugin …），你跑在整个桌面的 DOM 里，裸写 p {…} 会污染全站。
  • 毛玻璃只能写 backdrop-filter: blur(var(--surface-blur-3)); 这类系统令牌，禁止手写 blur(12px)（static-check 会判失败）。文字色用 var(--surface-text)。为什么、还有哪些令牌，见表面。

图标规则（硬性）

  • 应用图标一律 PNG，禁止 SVG（程序坞 / 启动台 / 商店共用同一张位图）。
  • 先到 assets/icons/（含 dock/、folder/ 子目录）找现成的，找到就复制进插件目录，manifest.icon 只写裸文件名（如 "icon.png"）——ZIP 分发要求插件目录自包含，库里原文件不要移走。
  • 实在没有合适的就不写 icon 字段，系统自动落占位图（assets/icons/dock/Launcher.png）。不引用、不凑数、不自绘。

最容易踩的坑（冷加载两条铁律）

  1. 入口脚本每次打开都重跑（系统故意用全新 URL 注入它），它注册的全局监听、定时器、window.__* 钩子不会被自动回收——必须在 plugin-unload 回调里亲手释放，否则越开越卡、菜单越堆越多。
  2. 被 import 的子模块只有一份实例（URL 稳定，跨打开复用）——所以 init() 要自己复位状态，订阅先去重，不能假设「这次打开 = 干净状态」。原理见冷加载机制。
跑通标准 程序坞出现你的图标 → 点击开窗、红绿灯能关能拖 → node dev/static-check.mjs 全绿 → 「调试 → 重载当前插件」后界面不叠影、监听不翻倍。
