开发自检工具

五个 Node 脚本 + 应用内自检。全绿 = 退出码 0；断言条数随定义表增长，别把打印的数字当契约。

脚本一览

脚本跑什么什么时候跑
node dev/static-check.mjs 不执行模块的磁盘一致性：import 说明符指向的文件在不在、说明符与 <script src> 上有没有误挂 ?v=、 代码/HTML 引用的 assets 是否真存在（404）、四语言包键位齐不齐、data-i18n 指向的键在不在、 面板 paneId 与注册表对不上、manifest 声明的文件在不在插件目录、模糊值是否走系统令牌、 墙纸着色是否乘 --tint-strength、permissions 三方对齐（PERMISSION_NAMES / LABELS / manifest 声明） 新增插件、改名或移动资源、动文案键、改 backdrop-filter / 墙纸着色规则
node --experimental-vm-modules dev/deep-check.mjs 深度静态审计：全部 JS 模块的 import 说明符与导出符号表（当前 147 模块 / 390 import） 动了内核模块结构后
node dev/settings-fulltest.mjs 每一条设置项：默认值合法、落盘文本、读回一致、非法值拒绝/钳制、reset、与 owner 历史键逐字一致、 pane/control 与系统设置注册表对得上（当前 72 项遍历） 增删设置项、改 pane/control
node dev/settings-harness.mjs 设置中枢 + 日志系统本身的行为（槽名推导、on/off、钳制、拒绝、jsonPath、订阅退订、门槛、留存、缓冲上限） 动过 settings.js / log.js 时
node dev/osfs-check.mjs OSFS 双后端行为（move / ConflictError / 顶层保护 / scope 沙箱） 动过 osfs.js / trash.js 时

另：dev/package-plugin.mjs <id> 导出 ZIP（打包即校验）；dev/store-check.mjs （商店逻辑，Node 18 下 vm.SyntheticModule 不可用会失败——环境问题，非代码错）。

运行前置 仓库没有 package.json（无构建链设计）。Node 20+ 直接跑； Node 18 需要临时建一个 { "type": "module" } 的 package.json（跑完删掉）—— 否则动态 import 项目 .js 会按 CJS 解析报「Cannot use import statement outside a module」。

应用内自检（真实浏览器存储上）

  • runSelfTest()（debug.js）：遍历 settings.list()，逐项「写探针值 → 回读比对 → 查存储槽 → 判 isDefault → 还原用户原值」，弹窗报告并可跳运行记录；
  • 「调试」菜单：查看运行记录 / 清空 / 导出 / 复制 / 切门槛 / 重载当前插件（验证 plugin-unload 是否清干净） / 输出设置表 / 层级体检；
  • 顶栏「调试」菜单由 debug.developerMode 门控（只门控菜单显隐，不门控日志系统本身）。
