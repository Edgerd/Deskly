文件存储 OSFS

单一根目录、双后端（virtual / disk）、插件作用域沙箱。import { OSFS } 或用全局 window.__osfs。

两个后端（插件代码不感知差别）

后端什么时候内容在哪
virtual（默认）没挂载真实文件夹；扩展形态（chrome-extension:// 没有目录选择器）恒是这个应用自己的 IndexedDB（库 webstartos-vfs，仓库 virtualfiles，keyPath: path）
disk用户选过本地文件夹作根且读写权限在那个真实文件夹，路径逐段映射；顶层骨架由内核 create

固定顶层目录（OSFS.TOP）

OSFS.TOP.documents.path   // "/文档"
OSFS.TOP.downloads.path   // "/下载"
OSFS.TOP.pictures.path    // "/图片"
OSFS.TOP.desktop.path     // "/桌面"
OSFS.TOP.trash.path       // "/废纸篓"（internal: 预建骨架，内容可操作、夹本身保护）
OSFS.TOP.appdata.path     // "/AppData"（internal === true：插件内部目录，不参与聚焦搜索）
别在插件里写 "/文档" 字面量——一律 OSFS.TOP.xxx.path； 也别再造「虚拟目录层」：内核的树已能存目录行（OSFS.move / mkdir / 目录行都是真操作）。

插件私有数据（作用域）

const me = OSFS.scope("notepad");       // → /AppData/notepad
await me.ensure();                       // 预建 temp / config / data
await me.write("temp/draft.json", text);
await me.write("config/layout.json", json);
await me.clearTemp();                   // 只清 temp

Deskly.fs 的五条方法（read/write/list/mkdir/remove）就是 scope(id) 的薄壳， 写自动补父目录，不必先 mkdir。

五条约定（违反任何一条都会变成 bug）

  1. temp 不可依赖持久性：可能被手删、被「清空缓存」清、被浏览器回收——读不到就当缓存未命中， 不许当错误，也不许当数据库。
  2. config 的真相源仍是 __settings（localStorage 槽）：冷启动要同步读的东西不能搬进文件； config/ 只放插件主动写出的副本/导出，读它必须容忍缺失。
  3. 权限过期不静默回落：挂载存在但 readwrite 没批时，disk 后端调用抛 NeedsReauthError（按 err.name 判别，别匹配 message）。界面要如实说「需要重新授权」， 绝不写「已保存」——两个互相覆盖的真相比报错严重得多。
  4. unmount 只忘句柄不删盘：OSFS.unmount() 不删磁盘上任何东西；remove() 拒删根与顶层夹； 取消挂载也不会把内容搬回应用内根——它留在那个文件夹里，重新挂载才看得见。
  5. 读路径有 1 秒元数据索引（metaIndex）：本标签页写入立即生效，另一个标签页最坏 1 秒后可见； 写路径不受影响（一律回库确认）。

OSFS.mount() / reauthorize() 必须在用户手势里调（非手势上下文 Chrome 直接拒）。

顶层保护

/废纸篓 等 TOP 夹本身不可 remove / move（用户手建在根上的普通文件夹照删不误）； 内容操作（list / 写条目 / 删条目 / 递归删）正常。UI 侧「删东西」的收口是 trash.js 的 emptyTrash()，OSFS.remove 不再被 UI 直接调用。
