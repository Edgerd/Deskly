## 2. 审查方法与依据

方法：HTTP 抓取 Apple 官方 Mac 使用手册正文，与实现逐项对照；未启动任何浏览器自动化。

引用页面（均为 macOS Sequoia 15 版）：

- P1 在 Mac 上平铺窗口 — support.apple.com/zh-cn/guide/mac-help/mchlef287e5d/15.0/mac/15.0
- P2 Mac 窗口平铺图标与键盘快捷键 — .../mchl9674d0b0/15.0/mac/15.0
- P3 在 Mac 上移动和排列 App 窗口 — .../mchlp2469/15.0/mac/15.0
- P4 在 Mac 上的全屏幕模式下使用 App — .../mchl9c21d2be/15.0/mac/15.0
- P5 在 Mac 上的分屏浏览视图中使用 App — .../mchl4fbe2921/15.0/mac/15.0

官方要点摘录（对照基准）：

- 指针放在绿色按钮上时，**平铺图标显示在出现的菜单里**（P2 原文），菜单结构为「移动与调整大小 / 填充与排列 / 全屏幕」三段，「全屏幕」有二级「整个屏幕 / 屏幕左侧 / 屏幕右侧」（P1/P2/P5）。
- 点按绿色按钮 = 进入全屏幕（P4）；最大化（填充桌面但不全屏）走菜单「填充与排列」下的填充图标或 Fn-Control-F，**再次 Option+点按绿键**返回之前大小（P3）。
- 键盘：Fn-Control-F 填充、Fn-Control-C 居中、Fn-Control-方向键 半屏、Fn-Control-R 恢复上一个大小、Fn-Control-Shift-方向键 双窗口排列（P2）。
- 拖到屏幕边缘/角平铺、拖到菜单栏填满桌面；按住 Option 拖到高亮区快速平铺（P1）。
- 连按标题栏可设为「填充」（P3）。

关于用户指出的不复刻点（绿色按钮悬停时平铺图标出现在弹层菜单而非按钮上）：该描述与 P2 官方行为一致——macOS 按钮本体悬停只浮出「关闭 ×、最小化 −、绿键展开双三角」三个符号，平铺图标本就该在菜单里。**当前实现的真正问题是按钮上的三个符号根本没渲染出来**（见 TL-01），用户才只看到菜单。

## 4. 问题清单

### TL-01【致命】悬停符号三个全部不渲染（用户报告现象的根源）

- 现状：`GLYPHS` 里 SVG 笔画/填充引用 `--traffic-glyph-close`、`--traffic-glyph-min`、`--traffic-glyph-zoom`（trafficLights.js L51-53），但这三个令牌**全项目无任何定义**（Grep 全仓仅命中引用处）。`var()` 无回退值 → 声明在计算值时失效 → stroke 回落初始值 `none`、fill 回落初始值 `black`。
- macOS 行为：悬停灯组时红键显深红 ×（#4d0000 系）、黄键显深棕 −（#995700 系）、绿键显深绿（#006500 系）外展双三角。
- 实际表现：× 和 − 完全不可见；绿三角显示为**纯黑**（fill 初始值），不是深绿。用户在绿色按钮上只看到 900ms 后弹出的菜单，形成「平铺图标只在菜单里、按钮上什么都没有」的体验。
- 证据：trafficLights.js L51-53（引用未定义令牌）；trafficlights.css L12-36（`:root` 令牌表无这三项）。
- 修复要点：在 trafficlights.css `:root` 补 `--traffic-glyph-close: #4d0000; --traffic-glyph-min: #995700; --traffic-glyph-zoom: #006500;`，dark 主题下提亮（约 #ff9f97 / #ffd60a 系深底色保可读，实际 macOS dark 下符号保持深色），并顺手在 GLYPHS 里加回退值兜底：`stroke="var(--traffic-glyph-close, #4d0000)"`。同时定义缺失的 `--traffic-inactive`（见 TL-07）。
- 验证：悬停任一窗口灯组，三符号同显且 ×/−/双三角颜色为深红/深棕/深绿；dev 工具 computed 面板确认令牌有值。
- 状态：待修复

### TL-02【致命】悬停弹菜单的热区是整个红绿灯组，不是绿键

- 现状：`lights.addEventListener("pointerenter", …)`（window-manager.js L1289-1302）——指针进入**任意一颗灯或灯组间隙**就开始计时 900ms 弹菜单。macOS 只有指针放在**绿色按钮**上才弹（P1/P2 原文均为「将指针放在…绿色按钮上」）。
- 影响：想点关闭/最小化时指针刚入灯区菜单就可能弹出遮挡，误触率高的同时还加剧了「符号没有、只有菜单」的观感。
- 证据：window-manager.js L1289-1302；组件未按按钮区分上报悬停（trafficLights.js 只有 contextmenu 按 zoom 过滤，L248-259）。
- 修复要点：在组件 shadow 内给 zoom dot 单独绑 `pointerenter/pointerleave`，以 CustomEvent（如 `deskly:zoom-hover`，composed）上报；window-manager 改听该事件。或在外层监听 pointermove 并用 `e.composedPath()` 判定目标 dot 的 `data-action === "zoom"`。
- 验证：悬停红/黄键 900ms 不弹菜单；悬停绿键弹出；对话框/禁用时（no-zoom、inactive）不弹。
- 状态：待修复

### TL-03【致命】绿键点击语义与 macOS 15 相反

- 现状：点击绿键 = `setZoom`（缩放填充桌面），Alt/⌘+点击 = `setFullscreen`（window-manager.js L1281-1283；旧标记形态 L1328 同）。
- macOS 行为：点按绿键 = **进入全屏幕**（P4）；最大化填充桌面走菜单/Fn-Control-F；**Option+点按绿键** = 返回之前大小（P3）。
- 影响：核心交互语义颠倒，老 Mac 用户肌肉记忆全错。
- 修复要点：交换默认映射——click → `setFullscreen`，altKey → `setZoom`/还原（已全屏时 click → 退出全屏）。如担心浏览器内全屏（隐藏菜单栏/Dock）过重，可保留现状但必须在「桌面与程序坞」设置里给出开关并在报告层面记录为有意偏差；保真目标下应交换。
- 验证：单击绿键进全屏（菜单栏/Dock 收起）；全屏中单击绿键退出；Option+单击在填充/还原间切换。
- 状态：待修复

### TL-04【高】悬停菜单结构与 macOS 15 三段式不符：无图标、无二级、无「填充与排列」

- 现状：扁平文本列表——header「窗口排列」+ 进入全屏/缩放填充/四个半屏/四个角/居中/还原（window-manager.js `windowMenuItems` L1212-1243）。无平铺图标、无「全屏幕」二级菜单、无 Option 动态布局项。
- macOS 行为（P1/P2）：三段分组——「移动与调整大小」（填充、居中、左/右/上/下半、四角，**每项前带平铺示意图标**）；「填充与排列」（左侧与右侧、四等分等多窗口布局，按 Option 出更多）；「全屏幕」（悬停出二级：整个屏幕/屏幕左侧/屏幕右侧）。
- 证据：window-manager.js L1212-1243；contextMenu.js L89-115（菜单项只有 label/checked/hasSubmenu，**无图标字段**）。
- 修复要点：① contextMenu 项扩展 `icon` 字段（受控 SVG 常量，禁外部输入），左侧 16px 图标列；② 菜单重排为三段 header：移动与调整大小 / 填充与排列 / 全屏幕（`hasSubmenu` › 已有，action 同坐标弹二级 L99-108 可复用）；③ 监听 Option 按下动态增删布局项（macOS 实时切换，不重开菜单）。
- 验证：菜单视觉与 P2 图标表逐项对得上；「全屏幕 ›」悬停出二级含三项。
- 状态：待修复

### TL-05【高】平铺键盘快捷键整体缺失

- 现状：keyboard.js ENTRIES（L56-89）无任何平铺键位；全仓搜不到 Fn/平铺快捷键实现。
- macOS 行为（P2）：Fn-Control-F 填充、Fn-Control-C 居中、Fn-Control-←/→/↑/↓ 半屏、Fn-Control-R 恢复、Fn-Control-Shift-方向键 双窗口排列。
- 约束：浏览器拿不到 Fn 键（Fn+方向键在多数键盘上映射为 Home/End/PgUp/PgDn 或不发事件）。
- 修复要点：采用可落键位映射并在 UI 明示——建议 Ctrl+Alt+←/→/↑/↓ = 半屏、Ctrl+Alt+Enter = 填充、Ctrl+Alt+C = 居中、Ctrl+Alt+R = 还原，写进 keyboard.js ENTRIES（tier: native）、finderbar「窗口」菜单 shortcut 列与设置-键盘面板。
- 验证：按键直接触发对应平铺；菜单显示快捷键标注。
- 状态：待修复

### TL-06【高】悬停弹出/收起时机偏离

- 现状：`HOVER_MENU_DELAY = 900`ms（window-manager.js L58）；菜单 `mouseleave` 后 160ms 关闭（L1265）。
- macOS 行为：悬停绿键约 0.4–0.5s 弹出；指针从绿键移向菜单不关闭，移出菜单后约 0.3s 内收起。
- 修复要点：弹出降至 450–500ms；收起延至 ~300ms，并加「指针正从灯区向菜单移动」容错（记录 pointermove 方向或给菜单上加 hover 桥区）。
- 验证：计时采样对比真机；绿键→菜单斜向移动不闪断。
- 状态：待修复

### TL-07【中】非活跃灰态色值缺失且深浅主题一刀切

- 现状：`:host(.inactive) .dot { background: var(--traffic-inactive, #d4d4d4) }`（trafficLights.js L99），`--traffic-inactive` 全仓未定义，深色主题下同色浅灰。
- macOS 行为：浅色主题非活跃灯 ≈ #d6d6d6 带细描边；深色主题 ≈ 深灰（约 #5f5f5f 系），对比均明显弱于活跃三色。
- 修复要点：trafficlights.css 定义 `--traffic-inactive: #d6d6d6`，`html[data-theme="dark"]` 下给深色值（如 #555555）。注意保持「非活跃灯仍可点击激活窗口」现状（macOS 如此，当前实现正确，勿加 pointer-events:none）。
- 验证：双窗口切焦点截图对比真机两主题。
- 状态：待修复

### TL-08【中】缺「全屏幕」二级菜单与分屏浏览入口

- 现状：菜单只有一行「进入全屏/退出全屏」（L1218-1220）。
- macOS 行为（P4/P5）：「全屏幕」二级含「整个屏幕 / 屏幕左侧 / 屏幕右侧」，左右半进入分屏浏览视图；分屏中绿键菜单还有「替换拼贴窗口 / 将窗口移到桌面」。
- 修复要点：先落二级结构（hasSubmenu 复用）；「整个屏幕」接现有 setFullscreen；「屏幕左侧/右侧」第一版可映射为全屏态+半屏拼贴占位，并在项上标注限制，后续再接真分屏空间。
- 验证：二级三项可达；整屏项行为与 TL-03 联动一致。
- 状态：待修复

### TL-09【中】Option 修饰链缺失（菜单更多布局、Option+拖拽快速平铺、Option+点绿键还原）

- 现状：菜单不看 Option；拖拽吸附不看 altKey（move 里 `snapZoneAt(ev.clientX, ev.clientY)`，L1114）；Option+点绿键当前被占用来做全屏（见 TL-03，交换后让位）。
- macOS 行为（P1/P3）：菜单内按 Option 显示更多布局；按住 Option 拖向高亮区松手即平铺；Option+点绿键在填充后还原上一大小。
- 修复要点：菜单打开期间 keydown/keyup(Alt) 重渲染布局项；拖拽中按住 Alt 放宽吸附触发距离/直接显示预览；绿键 alt 路径改为 zoom 还原。
- 验证：三条修饰路径各自生效且互不抢键。
- 状态：待修复

### TL-10【中】「填充与排列」多窗口布局未实现

- 现状：菜单无该分组；`tile()` 只操作单窗口。
- macOS 行为（P2）：左侧与右侧 / 右侧与左侧 / 顶部与底部 / 底部与顶部 / 四等分 / 半屏+四等分组合，把活跃窗口与次顶层窗口一起排。
- 修复要点：取窗口栈次顶层（zindex.js 有层级表）参与排列，先实现左+右/右+左/四等分三项，余者标注后续。
- 验证：双窗口场景选「左侧与右侧」，两窗各占半屏。
- 状态：待修复

### TL-11【中】窗口间对齐吸附未实现

- 修复要点：move 里追加对其他顶层窗口边缘的近距（~8px）磁吸判定，优先级低于屏幕分区吸附。
- 验证：两窗靠近拖动，边缘吸住。
- 状态：待修复

### TL-13【低】全屏/分屏中标题栏与灯的显隐

- 修复要点：`html.deskly-fullscreen` 下对当前全屏窗口标题栏做同样的顶边探出（用 top/visibility，禁用 transform——毛玻璃禁忌见 windowframe.css L7-10）。

### TL-14【低】标题栏高度 38px 系项目既定标准，记录为有意偏差

- 处置：若为整体视觉缩放决策则保留，但在设计文档中登记为有意偏差；红绿灯垂直居中已自动跟随，无需改动。

### TL-15【低】悬停提亮/压暗实现方式差异

- 现状：shadow 内 `filter: brightness(1.08/0.9)`（trafficLights.js L96-97）；旧标记形态用 inset box-shadow 遮罩（trafficlights.css L96-102，注释说明避开 backdrop-filter 重分层鬼影）。
- 风险：shadow 内 filter 不经过外层亚克力祖先，暂无鬼影报告；但与旧形态视觉不一致（遮罩 vs 滤镜提亮幅度不同）。

### TL-16【低】绿键长按/右键入口与菜单位置细节

- 现状：右键绿键 = 排列菜单（trafficLights.js L248-259，macOS 右键绿键无此菜单，属增强，保留）；无长按支持；菜单锚定 `r.left, r.bottom + 6`（window-manager.js L1300），即灯组左缘而非绿键下方。

- 修复要点：锚点改用 zoom dot 的 `getBoundingClientRect()`（组件上报该 rect）；长按（pointerdown ≥500ms 无移动）视同悬停触发。
