事件与全局接口

桌面里全部 CustomEvent 的地图 + window.__* 全局钩子速查 + 菜单 cmd 字符串规则。每个事件名、每个钩子都在源码里核实过。

插件生命周期事件（注册表与装载器派发）

全部在 document 上派发（bubbles: true），window 与 document 上监听都能收到。

事件detail谁发 / 什么时候
plugins-ready{plugins}plugin-manager：注册表就绪（内置插件全部注册 + ZIP 还原完成）
plugin-registered完整 manifest 对象app-registry：每个插件注册时（权限账本的 grantAll 挂在这里）
plugin-unregistered{id}app-registry：插件被卸载/移除（账本清账、默认应用清理挂在这里）
plugin-app-load{id, appId, windowName, el}plugin-manager：多应用插件每个应用窗口就绪（外壳只注一次）
plugin-app-open{id, appId, windowName, file}plugin-manager：访达带文件打开（窗口复用也发）
plugin-app-unload{id, appId}plugin-manager：关掉多应用插件的其中一个窗口
plugin-unload{id}plugin-manager：插件无存活窗口。你的全局监听 / 定时器 / __ 钩子都在这里释放

状态广播（document，detail = 对象，bubbles: true）

事件detail语义
settings-changed{key, value, previous, persisted, type}设置中枢写入（同值不广播）
languagechange{lang}语言切换（i18n.onChange 的底层事件）
trash-changed{empty}废纸篓增删成功（驱动 Dock 满/空图标）
trash-icon-change变体键用户切换废纸篓图标变体
default-apps-changed{key, appId, action, persisted}默认应用改绑 / 重置 / 插件移除连带清理
自定义 topic任意经 Deskly.bus.emit(topic, data) 或内核 app-registry.broadcast()（形状相同）

window.__* 全局钩子速查

这些钩子由内核模块在求值时挂上，插件可直接使用（来源文件逐条核实）：

钩子能力来源
__settings设置中枢（define/get/set/on/…）settings.js · 详见
__log日志（info/warn/error/debug/for/timer/…）log.js · 详见
__dialog系统弹窗旧门面：alert / error / confirm / prompt / messageBox。新代码用 Deskly.ui.dialog；权限框不在其列ui/dialog.js · 详见
__notify站内通知：show(opts) / dismissAll() / pendingCount() / resetPendingCount()ui/notification.js
__popover下拉浮层：open({anchor, content, …})（能伸出插件窗口）/ close / closeAll / openCount / zui/popover.js
__dock程序坞：minimizeToDock / restoreFromDock / setBadge / addToDock / updateRecents / syncRunningApps / getDockIconImg / resetDockLayout / getDockLayoutSnapshotdock.js
__osfs文件存储osfs.js · 详见
__surface模糊等级与文字令牌surface.js · 详见
__trash废纸篓闭环trash.js · 详见
__sound / __display / __lock / __spotlight音效 / 显示 / 锁屏 / 聚焦搜索各自 owner 接口对应模块
__permissions浏览器 Permissions API（通知/定位等）只读查询——和插件授权账本 __grants 是两回事，别混permissions.js
__launchpad启动台开关（isOpen / open / close / reopen）mods/launchpad
__getPluginByName / __getAppByName / __pluginManagerReady按显示名解析插件/应用记录、等注册表就绪app-registry.js
__menuActions菜单命令注册表（你加的键必须在 plugin-unload 里 delete）finderbar.js
__grants权限账本只读诊断面（isGranted / describe / listGrants…；写入口不全局暴露）api-grants.js
__defaultApps默认应用诊断面（SYSTEM_DEFAULTS 等）default-apps.js

菜单 cmd 语法（字符串形态只有两种合法）

name                 // 注册表里的键名
name('arg')          // + 至多一个字符串实参

其它任何 JS 表达式一律被拒绝并打日志——MV3 扩展页默认 CSP 是 script-src 'self'，new Function / eval 根本执行不了。 JS 代码里写的菜单表可以把 cmd 放成函数（内核内置插件这么用），但 HTML 属性 cmd="…" 读出来永远是字符串，只能写键名。
