废纸篓闭环 trash.js

/废纸篓 的唯一读写入口。UI 侧所有「删除」都经这里收口，业务代码不再直接调 OSFS.remove。源码：src/javascripts/trash.js。

为什么有它

直接 OSFS.remove 是硬删——「删了就找不回」。闭环之后的完整体验： 拖/移文件进废纸篓 → Dock 图标变满 → 访达里能看到 → 「放回原处」可撤销 → 「清倒」弹确认且真删。

模块与事件

import { moveToTrash, putBack, dropFileToTrash, emptyTrash,
         isTrashNotEmpty, TRASH_ORIGIN_SUFFIX } from "./trash.js";
// 或全局：globalThis.__trash（模块顶层自挂）

document.addEventListener("trash-changed", (e) => {
  e.detail.empty;   // 是否已空（图标满/空态、界面刷新都看它）
});

API

函数语义返回
moveToTrash(srcPath)把文件/文件夹 OSFS.move 进 /废纸篓（唯一名顺延 a (1).txt，不覆盖）， 并写溯源伴生文件 <名>.deskly-origin（JSON：{originalPath, movedAt}）{ok, path?, reason?}； reason: "notfound"（源不存在）/ "error"；NeedsReauthError 原样抛出
putBack(trashPath)读伴生文件还原到原路径；原目录没了落 /文档。 没有伴生的条目（从系统拖入的原生文件）返回 noorigin——调用方保持「放回原处」禁用，不编造原路径{ok, path?, reason?}
dropFileToTrash(file)Dock 拖入分支：原生 File 直接写进 /废纸篓（无溯源信息）{ok, path?}
emptyTrash()逐条递归移除（目录按 {recursive:true}）+ 清理伴生文件{ok, removed}
isTrashNotEmpty()满/空判定（伴生文件不算内容）boolean
desktopPathFor(name)生成 /桌面 下的唯一路径（同名顺延），桌面新建文件/文件夹用string

三条已接通的入口（勿再各造一套）

入口行为
桌面拖入文件 / 新建文件夹时内容落 /桌面（同名顺延不覆盖，改名同步记录）；右键「移到废纸篓」= moveToTrash； 遗留无记录的图标保持旧行为（只移除 DOM），不假装进过废纸篓
访达右键「删除」= 移入废纸篓；/废纸篓 内提供「放回原处」（有伴生才启用）+ 空白处右键「清倒废纸篓...」（带确认）； 视图自动过滤 .deskly-origin 伴生（那是记账文件，不是真实体）
程序坞拖 OS 文件进废纸篓 = dropFileToTrash；点击废纸篓 = 打开访达并导航到 /废纸篓（「前往」菜单也有该项）； 图标满/空由 trash-changed 驱动（「常规」变体自动切同色族「装满」版，显式黑白/透明变体不动，见 trashIcon.getTrashIconForFullness）

开发者规则

  • UI 侧删除统一走 moveToTrash / emptyTrash，不再直接 OSFS.remove（顶层夹内容除外）。
  • 伴生后缀常量 TRASH_ORIGIN_SUFFIX（".deskly-origin"）——你渲染 /废纸篓 列表时用它过滤。
  • NeedsReauthError 不要吞：权限未批时图标态保持现值、界面如实提示「需要重新授权」，别假装「是空的」。
  • 磁盘后端下，伴生文件会在用户的真实文件夹里可见（xxx.deskly-origin）——设计内行为，命名带 deskly 前缀便于识别。
