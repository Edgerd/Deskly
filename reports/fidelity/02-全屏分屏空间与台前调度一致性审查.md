> 判定口径：**必须复刻** = 用户高频可感知、且浏览器内可实现；**可降级** = 可实现但允许简化形态；**不适用** = 浏览器环境客观上做不到，须写明替代与后果。

### 3.1 全屏模式

---

#### FS-01 绿键默认动作与 macOS 相反（单击与 ⌥单击互换）

- 严重级别：**高**
- 判定：**必须复刻**

**macOS 15 依据**（官方页 2）：进入全屏的第一动作是「点按窗口左上角的绿色按钮」；官方页 6 写明最大化（填充）的鼠标路径是「按下 Option 键点按该按钮」。即：**单击绿键 = 全屏，⌥单击 = 缩放/填充**。

**项目现状（反转）**：

[window-manager.js](file:///e:/hello/StartOS/src/javascripts/window-manager.js#L13-L14) 头注：

```js
// 3. 绿键 = 缩放（填充菜单栏与程序坞之间的可视区），⌥点击 = 全屏，
```

[window-manager.js](file:///e:/hello/StartOS/src/javascripts/window-manager.js#L1281-L1284)：

```js
else if (detail.action === "zoom") {
  if (detail.altKey || detail.metaKey) setFullscreen(el);
  else setZoom(el);
}
```

旧标记形态同样反转：[window-manager.js](file:///e:/hello/StartOS/src/javascripts/window-manager.js#L1328) `e.altKey ? setFullscreen(el) : setZoom(el)`。

**影响**：每个第一次使用本项目的 macOS 用户，第一下绿键点击得到的结果都与肌肉记忆相反——想进全屏得到缩放，且本项目把「全屏」藏进了修饰键。这是全屏链路的入口级错误。

**建议**：翻转默认映射——单击 = `setFullscreen`，⌥单击 = `setZoom`（填充）。头注第 3 条同步改写。若担心现有用户习惯，可在系统设置加一项「绿键单击动作」（全屏/缩放），默认对齐 macOS。

#### FS-02 全屏不构成独立空间：其他窗口可压到全屏窗口之上

- 严重级别：**高**
- 判定：**必须复刻（以替代语义）**

**macOS 15 依据**（官方页 2、4）：全屏 App 独占一个空间；在该空间里只有这一个 App，要「去别的 App」必须离开该空间（手势/调度中心），不存在「普通窗口浮在全屏窗口上面」的状态。

**项目现状**：全屏只是「窗口尺寸 = 视口 + `<html>` 挂 `deskly-fullscreen`」，窗口仍留在同一个焦点栈里。

[window-manager.js](file:///e:/hello/StartOS/src/javascripts/window-manager.js#L418)：

```js
document.documentElement.classList.toggle("deskly-fullscreen", stack.some((w) => records.get(w) && records.get(w).fullscreen));
```

[window-manager.js](file:///e:/hello/StartOS/src/javascripts/window-manager.js#L330-L340) `focusWindow()` 无全屏守卫：全屏期间从 Dock 点开第二个应用，`pushStack + commitStack` 会把新窗口抬到全屏窗口之上；此时菜单栏仍收起着（`deskly-fullscreen` 未摘），用户看到一个悬浮窗漂在「全屏」画面上、顶部没有菜单栏——macOS 不存在这个状态。

**影响**：全屏沉浸感被任意一次 Dock 点击打破，且菜单栏显隐与「当前是否真在全屏空间」脱钩。

**建议**（替代语义，无需真空间）：`focusWindow` / `openApp` 路径加规则——焦点落到非全屏窗口时，若栈内有全屏窗口，自动给全屏窗口补一层「离开全屏空间」的语义：将全屏窗口临时压到栈底并隐藏（`visibility`），恢复非全屏环境的菜单栏；再次聚焦全屏窗口时复原。等价于用「同一视口内的伪空间切换」模拟 macOS 的空间滑动。

#### FS-03 多个全屏窗口无法并存与切换

- 严重级别：**高**
- 判定：**可降级**

**macOS 15 依据**（官方页 2）：「在全屏幕视图的其他 App 间移动：用三指或四指左右轻扫」；官方页 8：全屏 App 的缩略图出现在空间栏，可点按切换。

**项目现状**：`setFullscreen` 不阻止第二个窗口进入全屏，两个全屏窗口都 `displayFrame()` 覆盖视口，谁在上取决于栈序，且没有任何 UI 表达「现在有两个全屏空间」。

**影响**：第二个全屏把第一个永久盖住，用户只能 ⌃⌘F 退出当前这个才发现底下还有一个。

**建议**（降级形态）：实现 FS-02 的伪空间序列后，顺带得到全屏队列；切换入口两处：① 全屏时 ⌃← / ⌃→ 在全屏窗口序列中轮换（键位空闲，见 keyboard.js）；② 菜单栏「窗口」菜单列出全屏窗口清单。触控板三指轻扫属浏览器不可达手势，不实现（见 FS-06）。

#### FS-04 分屏浏览（Split View）整体缺失

- 严重级别：**高**
- 判定：**可降级**

**macOS 15 依据**（官方页 3、5）：入口 = 绿键悬停菜单「全屏幕 › 屏幕左侧 / 屏幕右侧」；随后在另一侧点选第二个 App；分屏浏览创建在新空间中；中间有分隔栏可拖动改占比、连按分隔栏恢复对半；可拖标题栏互换左右；绿键菜单有「替换拼贴窗口」「将窗口移到桌面」「全屏显示窗口」；退出后剩余 App 在自己的空间全屏显示。

**项目现状**：无任何分屏浏览实现。keyboard.js 第 71 行自述：

```js
{ id: "splitView", keys: "—", label: "分屏浏览", tier: "planned" },
```

绿键排列菜单（[window-manager.js](file:///e:/hello/StartOS/src/javascripts/window-manager.js#L1212-L1243)）只有「进入全屏」一项与全屏相关，无「屏幕左侧/右侧」子项。

**影响**：macOS 的招牌多任务能力整块缺席；现有的「左右平铺」是普通桌面内的几何半屏，菜单栏/Dock 不收起，也不是一个独立全屏空间，观感和语义都不是 Split View。

**建议**（降级形态，浏览器内可全量实现视觉部分）：
1. 绿键悬停菜单加「全屏幕」子菜单：整个屏幕 / 屏幕左侧 / 屏幕右侧（与官方页 5 的「全屏幕拼贴」表对齐）。
2. 选左/右侧后：当前窗口进入「分屏态」（新 rec 位，例如 `rec.split = "left"|"right"`），对侧弹出可选择窗口列表（复用调度中心缩略图思路，或简化为一张居中菜单列出其余可见窗口）。
3. 两侧就位后：菜单栏与 Dock 按全屏同一套收起；中间渲染 6px 分隔条，拖动改两侧占比（写入同一对 rec），连按恢复 50/50。
4. 退出：任一侧绿键 =「将窗口移到桌面」（退出分屏回 normal 框），另一侧升为独占全屏（按官方语义）；再退一次回到普通态。
5. 可继续降级砍掉：拖标题栏互换左右、替换拼贴窗口。

#### FS-05 台前调度是空壳：只有开关与桌面图标淡出

- 严重级别：**高**
- 判定：**必须复刻**

**macOS 15 依据**（官方页 7）：开启后「最近使用的 App 沿屏幕左侧整齐排列」「正在使用的窗口放在屏幕中央」；点左侧 App 切换；可把左侧 App 拖到中央组成群组；关闭「在台前调度中显示最近使用的 App」时左侧列表隐藏、指针贴左缘唤出；「显示应用程序窗口」可选一次全部/一次一个。

**项目现状**：控制中心卡片与设置键都已存在，但生效函数只做一件事——把桌面图标淡出。

[controlcenter.js](file:///e:/hello/StartOS/src/javascripts/controlcenter.js#L693-L700)：

```js
// ── 台前调度实现（窗口层级模式切换示意） ──
function applyStageManager() {
  const desktop = document.getElementById("desktop");
  if (!desktop) return;
  // 只切 class：样式在 assets/stylesheets/main/desktop.css（.desktop.stage-manager-on .item）。
  desktop.classList.toggle("stage-manager-on", !!state.stage);
}
```

[controlcenter.js](file:///e:/hello/StartOS/src/javascripts/controlcenter.js#L486) 注释自述：「Stage 走真实收纳（F-09 未落地前只切桌面图标）」。[desktop.css](file:///e:/hello/StartOS/assets/stylesheets/main/desktop.css#L53-L56) 只有 `opacity: 0; pointer-events: none`。

缺失清单（对照官方页 7 逐条）：当前舞台窗口组居中 **无**；其余窗口缩略停靠左侧 **无**；点缩略图切舞台 **无**；舞台切换过渡动画 **无**；窗口进出舞台规则 **无**；与 Dock/菜单栏配合 **无**；与全屏/分屏互斥 **未定义**。

**影响**：控制中心里一个看起来可用的开关，按下后窗口纹丝不动——属于「看起来能用其实不能用」一类，且是 macOS 12+ 之后用户熟知的核心功能。

**建议**：按第 5 节最小可用规格落地。

#### FS-06 多空间（Spaces）与调度中心整体缺失

- 严重级别：**高**
- 判定：**不适用（完整复刻）→ 以伪空间替代**

**macOS 15 依据**（官方页 4、8）：调度中心内可创建至多 16 个空间；空间栏显示全屏/分屏 App 缩略图；⌃←/⌃→ 或三/四指轻扫切换；拖窗口到屏幕边缘片刻后移到下一个空间；App 可「分配给」特定桌面；「切换到某个应用程序时，会切换到包含该应用程序的打开窗口的空间」。

**项目现状**：无调度中心、无空间栏、无空间概念。[keyboard.js](file:///e:/hello/StartOS/src/javascripts/keyboard.js#L68)：

```js
{ id: "mission", keys: "⌃↑", label: "调度中心", tier: "planned" },
```

`desktop.js` 全文无空间逻辑（仅图标/右键/拖入）。

**以什么替代**：
1. 不实现任意数量的桌面空间——浏览器新标签页是单视口单文档，多桌面在这里没有对应物。
2. 实现「全屏伪空间序列」（FS-02/FS-03）：全屏/分屏态各自视为一个虚拟空间，菜单栏「窗口」菜单与 ⌃←/⌃→ 提供枚举与切换。
3. 调度中心降级为「窗口总览」单层浮层：⌃↑ 打开，平铺显示所有可见窗口的静态缩略图（复用 genie-capture 快照管线），点按聚焦；顶部不做空间栏，只把全屏/分屏窗口排在第一行并加角标。
4. 「拖窗口到屏幕边缘换空间」「App 分配给空间」不实现。

**用户可感知的后果（必须写进设置/文档）**：无法把窗口组织到多个桌面；窗口多的时候只能靠最小化与台前调度收敛；全屏应用之间只能顺序轮换，没有空间栏缩略图的全局视图；触控板手势全部缺席。

#### FS-08 全屏进出动画：只有几何过渡，无空间语义

- 严重级别：**中**
- 判定：**可降级**

**macOS 15 依据**（官方页 2/8 的行为合成）：进全屏 = 窗口放大脱离桌面、桌面整体向旁滑出、进入独立空间，全程约 0.35–0.4s；退出反向。

**项目现状**：[frame.js](file:///e:/hello/StartOS/src/javascripts/wm/frame.js#L32) `WM_ANIM_MS = 320`；[windowframe.css](file:///e:/hello/StartOS/assets/stylesheets/ui/windowframe.css#L92-L94) `.window.wm-animating { transition: left/top/width/height 0.3s ease }`。菜单栏 `top` 过渡 0.18s（[windowframe.css](file:///e:/hello/StartOS/assets/stylesheets/ui/windowframe.css#L111-L117)）。窗口就地撑满，无桌面滑出/空间感。

**影响**：几何时长已接近（320ms 对 ≈350ms），差距在「语义」而非「快慢」：用户看到的是窗口变大，不是「换了一个空间」。

**建议**（降级形态）：进/出全屏时给桌面墙纸层与 Dock 加一个 320ms 的 opacity 交叉淡化（墙纸变暗 8–12% 再恢复），配合既有的菜单栏/Dock 收边，即可低成本传达「离开了桌面」。硬约束不变：`.window` 上禁止 transform/filter/clip-path（亚克力禁忌），任何滑移只能发生在墙纸层与缩略图层。

#### FS-09 绿键「窗口排列」菜单结构不符合 macOS 15

- 严重级别：**中**
- 判定：**必须复刻（结构对齐）**

**macOS 15 依据**（官方页 1、5）：绿键悬停菜单分组为：「全屏幕」（整个屏幕/屏幕左侧/屏幕右侧）、「移动与调整大小」（填充/居中/左/右/上/下半+四角）、「填充与排列」（多窗口布局，⌥ 展开更多）。

**项目现状**：[window-manager.js](file:///e:/hello/StartOS/src/javascripts/window-manager.js#L1212-L1243) `windowMenuItems` 为平铺列表：进入全屏 / 缩放填充 / 四个半边 / 四个角 / 居中 / 还原平铺前大小。无分组标题层级（只有一个「窗口排列」header）、无全屏幕子菜单、无多窗口排列项。悬停延时 900ms 是头注写明的设计值（macOS ≈0.5s），属有意偏差，保留即可。

**建议**：重排为三组——「全屏幕」子菜单（整个屏幕/屏幕左侧/屏幕右侧，后两项接 FS-04）、「移动与调整大小」（现有四边四角 + 填充 + 居中）、⌥ 按下时追加「填充与排列」多窗口项（左+右/右+左/四等分，实现 = 对最上面 2~4 扇可见窗口依次调 `tile()`）。

## 5. 台前调度最小可用规格（落地用）

### 5.1 状态模型

新模块建议：`src/javascripts/wm/stage-manager.js`（与 genie-* 同层，window-manager 只挂钩子）。

```text
StageManager = {
  enabled: boolean                 // 唯一权威 = 设置键 controlcenter.stage
  activeSetId: string|null         // 当前舞台上的窗口组
  sets: Map<setId, {
    id: string,
    windows: HTMLElement[],        // 组内窗口（保持各自几何与 stack 序）
    anchor: HTMLElement,           // 组内最近聚焦窗口（缩略图与聚焦目标）
    lastUsed: number               // 停靠区排序依据
  }>,
  order: string[]                  // 停靠区从上到下 = lastUsed 降序
  settings: {
    showRecent: boolean            // desktop.stage.showRecent，默认 true
    windowMode: "all" | "one"      // desktop.stage.windowMode，默认 "all"
    showDesktopItems: boolean      // desktop.stage.showDesktopItems，默认 false
    clickWallpaper: "always" | "stageOnly"  // desktop.stage.clickWallpaper，默认 "stageOnly"
  }
}
```

**窗口进出舞台规则**：
1. 开启瞬间：全部可见非最小化窗口按「应用名 + 聚焦历史」成组——同一应用的窗口合一组；最近聚焦的组上舞台，其余进停靠区。
2. 新打开窗口：加入当前舞台组（macOS 默认行为）。
3. 点停靠缩略图：该组上舞台（组内窗口摘 `wm-shelved`、按 `windowMode` 恢复全部或仅 anchor），原舞台组进停靠。
4. 拖窗口标题栏到某个停靠缩略图上松手：并入该组；拖到停靠区空白：单独成新组。
5. 组内最后一个窗口关闭/最小化：删组；舞台上的组空了：自动把 order 第一组升上舞台。
6. 再点一次当前舞台组的缩略图：`windowMode="one"` 时循环组内下一窗口（官方页 7 的语义）。
7. 点按墙纸：按 `clickWallpaper` 决定全部窗口进停靠（显示桌面）与否。

**与全屏/分屏的互斥**：`setFullscreen` / 分屏态入口先调 `stageManager.suspend()`（保留 sets，摘掉舞台呈现）；退出后 `resume()`。台前调度开启时不允许进入分屏浏览（macOS 同）；全屏允许但离台。

### 5.2 停靠区与舞台的视觉参数

- 停靠区：屏幕左缘固定条，缩略图宽 88px、高约 56px（16:10 视口比例压缩），圆角 8px，间距 12px，左内边距 12px；超过 5 个时向下延伸，超出部分折叠为「…」。
- 舞台窗口组：居中区域 = 视口扣除左停靠条（112px）后的区域；窗口保持用户几何，只是「不在组的窗口不可见」。
- 缩略图来源：**复用 `wm/genie-capture.js` 的快照管线**（已有 snapdom 截图与缓存），不进停靠区逐帧重截——进停靠截一次，组内几何变化时复用既有 `refreshWindow` 钩子。
- 非舞台组窗口本体：挂 `.wm-shelved`（`visibility: hidden` + `pointer-events: none`），**留在 stack 中不动层级**，避免 commitStack 重排抖动。

### 5.3 动画参数（与既有节奏统一）

| 动作 | 参数 | 说明 |
|---|---|---|
| 窗口上舞台 | 320ms `cubic-bezier(0.22,1,0.36,1)`，left/top/width/height + opacity | 与 WM_ANIM_MS / OPEN_ANIM 同族；从停靠位几何浮到用户几何 |
| 窗口入停靠 | 240ms 同曲线 | 缩到缩略图位后交叉淡入缩略图（缩略图是独立 DOM，**可以用 transform**；窗口本体仍禁 transform） |
| 舞台切换整组 | 交错 40ms/窗，上限 3 窗 | 同组多窗依次落位 |
| 缩略图 hover | 120ms 亮度 1.08 | 与红绿灯 hover 一致 |
| reduce-motion | 全部降级为纯 opacity 淡入淡出 | 走既有 `html[data-reduce-motion="on"]` 通道 |
