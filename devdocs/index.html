总览与架构

Deskly 是一个运行在 Chrome / Edge 新标签页里的 macOS Sequoia 桌面：纯 HTML/CSS/JS、MV3、零框架零构建。本站教你怎么给它写插件（mod），并解释系统是怎么拼起来的。

这是什么

  • 一个浏览器扩展（MV3）。装好以后，你打开每一个新标签页，看到的都是一整套模拟 macOS 的桌面：菜单栏、程序坞、窗口、启动台、控制中心。
  • 一套插件系统。每个应用（计算器、访达、记事本……）都是 mods/<id>/ 下的一个独立目录，系统自带一组内置插件（清单见 plugin-manager.js 的 BUILTIN_IDS），也可以通过应用商店安装第三方 ZIP 插件。
  • 一份开放的内部接口。插件通过 window.Deskly 申请系统能力（启动别的应用、读写文件、订阅事件），通过 window.__settings 注册自己的设置项，通过 i18n 做多语言。

它不是什么（三条最常见的误会）

误会真相
「插件跑在沙箱 iframe 里」不是。内置 mod 全部由 plugin-manager fetch 后注入宿主主文档，和桌面共享同一份 DOM。安全边界是 manifest 里的 permissions 声明 + api-grants.js 的授权账本，是「同意与记账」，不是隔离。
「有构建步骤，要装 npm 依赖」没有。仓库没有 package.json，浏览器直接跑源码。自检靠 dev/*.mjs 几个 Node 脚本（见开发自检工具）。
「window.Deskly 是全部接口」不是。Deskly 只是受权限门禁的那部分。设置（__settings）、日志（__log）、弹窗（Deskly.ui.dialog，旧名 __dialog）、通知（__notify）等全局钩子可以直接用，完整清单见事件与全局接口，弹窗细节见系统弹窗 dialog。

四层结构（改代码前先认清自己在哪层）

层位置内容改动约束
ui/ 框架src/javascripts/ui/（模块数以实测为准）弹窗、通知、浮层、右键菜单、窗口红绿灯、桌面图标跨插件复用；样式只走系统令牌
mods/ 应用mods/{id}/（内置插件清单见 BUILTIN_IDS，不写死数量）每个插件 = manifest.json + index.html + style.css + script.js + 图标目录自包含，可整体打成 ZIP 分发
src/ 内核src/javascripts/（50 个顶层模块，以脚本实测为准）程序坞、启动台、控制中心、设置中枢、日志、OSFS 文件存储、层级表、i18n、插件管理器……插件通过 import 与 window.__* 消费，不反改
assets/ 资源assets/icons|images|locales|…图标库、界面字形、四语言包（zh-CN / en / ja-JP / cat）应用图标一律 PNG；运行时文件名必须 ASCII

开发流程（最短路径）

  1. 跟做 五分钟写第一个插件：抄 mods/about/ 骨架 → 改 manifest → 注册 → 刷新看效果。
  2. 需要系统能力时查 window.Deskly 与 事件地图，把用到的权限名写进 manifest.permissions。
  3. 写样式只许用系统模糊令牌与文字令牌，写完过一遍红线清单。
  4. 收尾跑 static-check / deep-check / settings-fulltest，全绿再交付。

本文档的时效性怎么保证

每页页脚都标了适用版本（当前 0.4.3，取自 src/javascripts/version.js 的 VERSION 常量，与扩展 manifest 同步）。 文中所有 API 名、事件名、字段、数值都在该版本源码里逐条核对过；会随版本漂移的数字（模块数、断言数、设置项数）都注明了「以脚本实测为准」。
