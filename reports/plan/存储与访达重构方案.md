# 存储与访达重构方案

> 纯规划文档：不改代码、不改样式、不动 `devdocs/`。评审通过后再分期实施。
> 证据行号基于 2026-11-05 工作区快照。

---

## 0. 摘要

本次重构做四件事：把文件系统从"OSFS 混合体"拆成分层的统一文件系统层；让桌面成为 `/桌面` 目录的真实视图并补全 macOS 交互；把右键菜单与 Quick Look 改造成"内核组件 + provider 注册"模型并全部开放为公开 API；修掉访达"此文件夹为空"的遮挡 bug。全文分八章 + 参考来源。

根因速览（详见 1.1）：`mods/finder/style.css:591` 的 `.finder-empty { display: flex }` 覆盖了 `[hidden]` 的 UA 样式，`emptyEl.hidden = true`（`mods/finder/finder-views.js:228`）永远无效，空状态浮层（`position:absolute; inset:0; pointer-events:none`）因此常驻并压在已渲染的条目上。同文件 606-607 行 `.finder-quicklook[hidden] { display: none }` 正是别人修过的同类 bug，`.finder-empty` 漏了。

## 2. 目标架构

### 2.1 分层与依赖方向（严格自上而下，禁止反向与环）

```
┌─ 插件层  mods/finder · mods/office · mods/photos · mods/launchpad · 第三方插件
│            │ 只能调 Deskly.* 公开 API（内置插件收口见开放问题 Q6）
├─ 公开 API 层  os-api.js（Deskly.fs / Deskly.menus / Deskly.quicklook /
│              Deskly.openWith / Deskly.icons / Deskly.shortcuts）
│              │ 每个方法经 api-grants.js guard(权限)
├─ 服务层    core/contextmenu（菜单装配器）· core/quicklook（预览宿主）
│            core/openwith（类型→应用路由）· core/shortcuts（快捷方式）
│            │ 只依赖领域层
├─ 领域层    fs/vfs-view（统一视图）· fs/tags · fs/index（元数据索引）
│            fs/events（fs-changed 总线）
│            │ 只依赖引擎层
├─ 引擎层    fs/core（路径/节点/事务/原子写/配额）· fs/mounts（挂载表）
│            fs/backends/virtual · fs/backends/disk（实现统一 Backend 接口）
└─ 存储层    IndexedDB（虚拟后端）· File System Access API（磁盘后端）
```

规则：
- **Backend 接口**是引擎层内部契约（`list/read/write/mkdir/remove/stat/move/copy`，全部 async，抛带 `code` 的 `FSError`）；virtual 与 disk 各自实现，`fs/core` 按挂载表路由，消除 F2 的内联分派。
- **统一视图（vfs-view）**：虚拟树 + 挂载点在同一棵树上合并输出；挂载点未授权时输出"待授权"占位节点（现状已有雏形，`src/javascripts/vfs.js:163-209`，收编进领域层）。
- **事件总线**：`fs/events` 在每次写/删/移/挂载变化后广播 `fs-changed {op, paths[]}`；桌面、访达、废纸篓图标、Spotlight 索引全部改为订阅它（消灭 F5、D1 的"各自为政"）。
- **窗口系统**不依赖文件系统；Quick Look 宿主是服务层消费者，与 window-manager 只通过 z-index 契约交互（对齐 `reports/fidelity/03-窗口API盘点与设计.md` WAPI 清单，不在本期改窗口内核）。

### 2.2 模块文件级划分（目标态，新文件均放 `src/javascripts/fs/` 与 `src/javascripts/core/`）

| 文件 | 职责 | 不许做 |
|------|------|--------|
| `fs/core.js` | 路径规范化、FSError、事务编排、原子写、配额检测 | 不碰 IndexedDB API |
| `fs/backends/virtual.js` | IndexedDB CRUD | 不知挂载存在 |
| `fs/backends/disk.js` | FSA 句柄读写、`NeedsReauthError` | 不知虚拟库存在 |
| `fs/mounts.js` | 挂载表、句柄持久化/恢复、铺骨架 | 不做 UI 提示 |
| `fs/view.js` | 统一视图（合并+排序入参）、tags | 不渲染 |
| `fs/events.js` | `fs-changed` 派发/订阅 | 不写存储 |
| `core/contextmenu.js` | 菜单模型+装配（排序/分隔/⌥ 变体/禁用） | 不含具体条目 |
| `core/quicklook.js` | 预览窗宿主、键盘路由、provider 选择 | 不实现任何格式预览 |
| `core/openwith.js` | 类型注册表、默认应用、⌥「始终以此方式打开」 | 不启动窗口（交给 app-registry） |
| `core/shortcuts.js` | 桌面快捷方式读写（`.webloc.json` 落 `/桌面`） | 不渲染图标 |

`osfs.js` 退役为 `fs/*` 的兼容薄壳（仅导出转发，内置调用方逐期切换，最后一期删除）。

## 3. 数据模型与迁移

### 3.1 IndexedDB schema v2（库名不变 `webstartos-vfs`，version 1 → 2）

- `nodes`（keyPath: `path`）：`{ path, parent, name, type: 'file'|'folder', size, mtime, mime, tags: [], pos?: {x,y} /*桌面自由摆放*/, link?: {appId} /*快捷方式*/, blobId? }`，索引：`parent`、`tags`（multiEntry）。
- `blobs`（keyPath: `id`）：`{ id, data }`。内容与元数据分表，`list` 只读 `nodes`（解决 F1）。
- `mounts`：原 `handles` 表平移，加 `label`、`addedAt`。
- `meta`：`{ key: 'schema', version: 2, migratedAt, v1Retained: bool }`。

### 3.2 迁移策略

1. `onupgradeneeded` 建新表；升级事务内流式拷贝 `virtualfiles` → `nodes`+`blobs`，路径逐条校验（非法路径记入 `meta.migrationErrors` 并跳过，不中断）。
2. v1 旧表**保留不删**（`v1Retained: true`），迁移后首次完整跑通验收，下一期再删——回滚 = 把 `meta.schema` 标回 1 并清掉新表，旧数据原样还在。
3. 迁移失败（配额/中断）：升级事务整体回滚是 IndexedDB 原生保证；启动时检测 `meta` 缺失则重跑迁移。

### 3.3 统一视图规则

- 挂载点路径（如 `/文档` 被挂载到真实目录）在视图中只出现一次；磁盘后端失败（未授权）时该节点显示为"待授权"占位，不报错不消失（现状行为保留，`vfs.js:163-209`）。
- `stat` 统一返回 `{ path, name, type, size, mtime, mime, tags, origin: 'virtual'|'disk', reauth? }`——插件不感知后端（与 `devdocs/api/osfs.html:12-20` 承诺一致）。

### 3.4 原子性与配额

- 虚拟后端写 = 同一事务内 `blobs.put` + `nodes.put`；覆盖写先写新 blob 再切指针，失败时旧 blob 仍在（解决 F4）。
- 磁盘后端写 = 先写 `<name>.desklytmp` 再 `move` 改名覆盖（FSA 支持句柄 move；不支持的浏览器降级为"写新删旧"+失败时保留旧文件提示）。
- 磁盘后端 `move` 优先用原生 `handle.move()`，仅在不支持时回退复制+删除，回退路径失败时报 `EFSMOVEFAIL` 并保留源（解决 F3）。
- 配额：启动与每次写前 `navigator.storage.estimate()` 余量 < 写入大小×2 时抛 `EFSQUOTA`；`QuotaExceededError` 统一翻译为 `EFSQUOTA`。

### 3.5 错误码（全层统一）

`ENOENT / ENOTDIR / EISDIR / EEXIST / EPERM（保护路径）/ EREAUTH（挂载待授权）/ EFSQUOTA / EFSMOVEFAIL / EIO`。`FSError extends Error { code, path }`。

## 4. API 契约（公开面，均挂 `window.Deskly`，插件经 `api-grants` guard）

> 权限名沿用 `api-grants.js:30-47` 既有命名风格；标注【敏感】的走运行时确认弹窗（沿用 `api-grants.js:256-378` 的"仅这次/始终允许"），其余安装期声明即可。

### 4.1 `Deskly.fs`（扩展现有面，向后兼容）

| 方法 | 签名 | 权限 | 说明/错误 |
|------|------|------|-----------|
| read | `read(path) → Promise<File>` | files:read | 相对=沙箱，绝对=公开路径；`ENOENT/EREAUTH` |
| write | `write(path, data, opts?) → Promise<string>` | files:write【敏感=绝对路径】 | 原子写；`EEXIST`（`opts.exclusive`）、`EFSQUOTA` |
| list | `list(path, opts?) → Promise<Stat[]>` | files:read | `opts: {sort, tags}` |
| stat | `stat(path) → Promise<Stat>` | files:read | 统一 Stat 形态（3.3） |
| mkdir | `mkdir(path) → Promise<string>` | files:write | |
| remove | `remove(path, {trash=true}) → Promise<void>` | files:write | 默认进废纸篓（可放回原处），`{trash:false}` 直接删 |
| rename | `rename(path, newName) → Promise<string>` | files:write | 同目录改名；`EEXIST/EPERM` |
| move | `move(src, destDir) → Promise<string>` | files:write | 跨后端自动处理；同名顺延 `(1)` |
| copy | `copy(src, destDir) → Promise<string>` | files:write | |
| watch | `watch(path, cb) → unsubscribe` | files:read | 基于 `fs-changed` 的过滤订阅 |
| trash.* | `list/putBack/empty` | files:write | 收编 `trash.js` 能力 |

降级：磁盘后端不可用时 `EREAUTH` 结构化返回，插件可引导用户去访达重新授权；`watch` 在磁盘后端降级为轮询（5s），对插件透明。

最小示例：
```js
const doc = await Deskly.fs.write("/文档/周报.md", "# 周报", { exclusive: false });
Deskly.fs.watch("/文档", (changes) => render(changes));
```

### 4.2 `Deskly.menus`（右键菜单 provider API —— 桌面与访达共用）

```ts
Deskly.menus.registerProvider({
  id: "office",                       // 插件 id
  match: (sel) => boolean,            // sel: { items: Stat[], location: 'desktop'|'finder'|'launchpad', isBackground: bool }
  items: (sel) => MenuItem[],         // 见下
  order?: number                      // 默认 100；内建 provider 0-99
})
// MenuItem: { id, label, icon?, action(sel), submenu?: MenuItem[],
//   enabled?: boolean|(sel)=>boolean, separatorAfter?: boolean,
//   alt?: { label, action } }        // alt = 按住 ⌥ 时的替换项（macOS 语义）
```
- 装配器职责：内建条目（打开/打开方式/移到废纸篓…，固定顺序见 5.1）→ 插件条目按 `order` 插入 → 自动去重分隔线、裁掉连续/首尾分隔线 → ⌥ 键实时切换 alt 项。
- 权限：`menus:register`（非敏感）。插件 action 里再调 `fs` 仍需各自权限。
- 降级：`match` 抛错 = 该 provider 本次跳过并 console.warn，不影响其他 provider。

```js
Deskly.menus.registerProvider({
  id: "office",
  match: (sel) => sel.items.some(i => /\.(docx|xlsx|pptx)$/.test(i.name)),
  items: () => [{ id: "office.convert", label: "转换为 PDF…", action: (sel) => exportPdf(sel.items[0]) }],
});
```

### 4.3 `Deskly.quicklook`（预览 provider API）

```ts
Deskly.quicklook.registerProvider({
  id: "office",
  match: (stat) => number,            // 0=不匹配；数值大者胜出（内建图片/文本=10）
  render: (container, stat, ctx) => Promise<void|{ cleanup() }>,
  // ctx: { readFile(), signal: AbortSignal, zoom: {factor, set(f)} }
})
Deskly.quicklook.open(paths[], index?)  // 内核/桌面/访达共用入口
```
- 未知类型自动回退：图标 + 名称/大小/修改时间/种类（等同 macOS"无可用预览"）。
- 权限：`quicklook:register`（非敏感）；provider 内读文件走自身 `files:read` 沙箱规则——**预览他人文件由宿主读好字节通过 `ctx.readFile()` 喂给 provider**，provider 无需越权。
- 降级：provider `render` 超时 5s 或抛错 → 回退通用预览并标记来源。

### 4.4 文件类型注册（扩展 manifest，向后兼容现有 `formats`）

### 5.2 Quick Look（对齐 Apple Support mh14119，全部已核实）

- 空格开；**再按空格或点关闭按钮关闭**（官方页明示）；Esc 关闭（macOS 通用行为，官方页未列出，标注"通用行为未逐字核实"）。
- 多选打开显示首项；←/→ 切换；窗口跟随当前选中项（访达已有 `quicklook-navigate` 机制，保留并上移到内核）。
- ⌘+ / ⌘− 缩放图片；⌘Return 多项目索引表（**有意不实现**，列开放问题 Q4）；全屏按钮（有意不实现，与窗口系统重写联动后再说）。
- 文件夹：显示文件夹图标 + 项目计数 + 总大小（macOS 行为）；音视频：内建 `<video>/<audio>` 播放条；docx/xlsx/pptx：由 office 插件注册 provider（4.3）。
- 桌面同样生效（空格监听挂在桌面视图）。

### 5.3 保存流程（office/照片及所有走 `Deskly.fs.write` 的应用）

- **保存（⌘S/保存按钮）**：有路径→直接原子覆盖（macOS 自动保存语义，不弹确认）；无路径→走"另存为"。
- **另存为**：系统级保存面板组件（内核 `core/savepanel`，位置默认 `/文档`，可改名/选位置）；目标已存在→冲突对话框「替换 / 保留两者 / 取消」（macOS 标准三键）；"保留两者"自动顺延 `(1)`。
- **失败**：`EREAUTH`→面板内嵌"重新授权"引导；`EFSQUOTA`→明确文案"空间不足"；其他→错误对话框含错误码。失败不写半截文件（3.4 保证）。
- **照片迁移**：导入落 `/图片`（虚拟后端），旧私有库一次性迁移 + 保留只读副本一期。

### 5.4 废纸篓

- 清空前确认对话框，可在访达设置中关闭（macOS「清倒前显示警告」，已核实：Finder 设置→高级）；⌥+清倒 = 跳过确认（对应 macOS ⌥ 删锁定文件语义，社区来源）。
- 「放回原处」保留现有 `.deskly-origin` 机制（`trash.js:58-124`），收编进 `Deskly.fs.trash.*`。

## 7. 验证计划（无浏览器自动化）

## 8. 开放问题（已全部拍板，以下为最终决策，实施以此为准）

- **Q1 桌面坐标【已决策】**：存目录级 sidecar `.DS_Store`（自定格式，带版本号）。要求：对用户与访达/桌面完全隐藏（不进列表、不可选中/重命名、不进搜索、右键菜单不出现）；损坏回退默认网格不报错；跨后端一律生效；移动/复制目录时随目录走；同名冲突不得覆盖用户真实文件。**影响范围**：第 1 期错误码/隐藏过滤，第 2 期桌面视图。
- **Q2 照片库【已决策】**：不做迁移，以根目录 `/Picture/` 为唯一照片库；应用启动自动扫描；支持添加文件；支持挂载外部图片文件夹（授权后只读/读写，越界一律拒绝）；旧私有库逻辑删除，不留旁路。**影响范围**：第 4 期。
- **Q3 压缩【已决策】**：只实现「压缩」（ZIP store 模式，不引入压缩算法）；「制作替身」「共享」不做也不占位（菜单不出现、代码不留空函数、文档不承诺）。**影响范围**：第 3 期菜单。
- **Q4 索引表 + 查看选项【已决策】**：⌘Return 多项目索引表本次必做（第 5 期）；「显示查看选项」并入系统设置，不另做浮层——本期只做数据与 API，设置面板落地等窗口改造放行。**影响范围**：第 5 期 + 待放行项。
- **Q5 Quick Look【已决策】**：全局单例，后开者接管；预览作为独立应用注册——启动台不可见、系统设置可见；新增应用可见性 API（声明是否出现在启动台/设置/访达应用列表），写进将来的开发文档清单。**影响范围**：第 3 期。
- **Q6 插件收口【已决策】**：不分期一次收口。finder/office/photos 全部只走 `Deskly.*`，禁止直接 import 内核模块或 `_closeWindow` 等私有钩子；读硬盘必须先授权，越界自动屏蔽（拒绝 + 可编程错误码，不静默降级）。**影响范围**：第 6 期。
