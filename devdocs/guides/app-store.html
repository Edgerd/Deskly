应用商店与分发

商店界面语义、ZIP 三级安装链、禁用 / 还原、发布流程。

界面语义（真实数据，不造条目）

  • 卡片列表 = 注册表里全部插件（内置 + 已安装 ZIP），没有「推荐位」这种造数；
  • 分类过滤是真实语义：卡片按 store.category 匹配，没写 store 的插件只在「全部」里出现；
  • 详情 = store 自声明 + 权限栏（读 manifest.permissions，经 api-grants.describe() 出人类可读文案，与授权账本同源）；
  • 「打开」调 load(插件id) → 多应用套件落到 apps[0]；
  • 「禁用」不删文件：注册表标记 disabled，Dock / 启动台灰显，重载扩展不会复活它。

ZIP 安装三级链（全部成功才算装上）

  1. 读包：拖入（或「安装 ZIP…」）→ 解包（JSZip，assets/vendor/jszip.min.js）→ 校验 manifest 在根 / 公共根、总字节 ≤ 10MB、id 与目录名一致；
  2. 落库：文件以 Blob 存 IndexedDB webstartos-plugins.installed（不写磁盘 mods/）， 注册表写入 _installed: true 标记；
  3. 接管验证：sw.js 拦截 ./mods/<id>/<file> 请求从库里回源，并在响应写 X-Deskly-Plugin 标记头。安装器请求一次带标记验证——接管不了（SW 没跑起来）就整段回滚，不留半装状态。
覆盖安装：同 id 再装一次 = 新包覆盖旧 Blob（store.meta 记账 + 安装历史记版本差异）。 旧版文件残留不会发生（按 id 整组替换）。

发布一个插件（完整流程）

  1. 在 mods/<id>/ 写完四个文件 + icon（规范见插件包格式）；
  2. 内置：把 id 加进 BUILTIN_IDS；第三方：不动 BUILTIN_IDS；
  3. 跑 node dev/static-check.mjs（第 7 节核对 permissions 声明齐不齐、manifest 声明的文件在不在）；
  4. 导出：node dev/package-plugin.mjs <id> → dist/<id>-<version>.zip（打包即校验，见上节）；
  5. 交付：对方在应用商店拖 ZIP 或点「安装 ZIP…」；权限按 api-grants 账本在安装/首调时授权（敏感权限逐次弹确认，见 Deskly）。

还原内置

卸载 ZIP 插件（或「还原内置」）后，IndexedDB 里的 Blob 删除、注册表条目移除； 内置插件文件在扩展包内（加载时整目录打进去），永不丢失——不存在「删了找不回」的内置。
