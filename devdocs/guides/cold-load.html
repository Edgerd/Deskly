冷加载机制

「启动只注册清单，点击才加载内容」——这页讲清楚它怎么工作，以及由此而来的两条硬约束。写插件踩的坑，一半出自这里。

这是什么 / 为什么这么设计

Deskly 开机要快。内置插件如果把全部界面、样式、脚本一次性加载，首屏会卡在几十个请求和几百万次 DOM 操作上。 所以系统分两个阶段：启动时只读每个插件的 manifest.json（几 KB），把名字、图标、入口登记进注册表； 真正的界面资源，等用户点击图标那一刻才拉取。注册快、启动快，代价是插件代码要写「可被反复装载卸载」的形态。

阶段一：启动注册（仅清单）

  1. plugin-manager 的 prefetchManifests() 按 BUILTIN_IDS（全部内置 id，数量随版本增长）并行拉取 ./mods/<id>/manifest.json?v=VERSION；
  2. 逐个 registerPlugin() 登记进注册表（每个注册都会广播 plugin-registered，权限账本靠它记账）；
  3. 从 IndexedDB 还原用户安装过的 ZIP 插件；
  4. markReady() 并广播 plugins-ready。程序坞、启动台、商店都监听这个事件渲染。

这一阶段不加载任何界面、样式、脚本。首屏打开 Network 面板，应该只看到与 BUILTIN_IDS 等量条的 manifest.json 请求（外加 ZIP 插件的）。

阶段二：点击加载（按需）

用户点击图标 → load(id) 按顺序（不是并行）拉三件资源：

  1. style.css → 包成 <link id="plugin-style-<id>"> 追加进 <head>，按 id 去重；
  2. index.html → fetch 后 insertAdjacentHTML("beforeend") 注入 body；
  3. script.js → 每次先移除旧脚本元素、再以全新 URL 注入新的；
  4. 新出现的 .window 交给 window-manager.manage() 绑定拖拽 / 缩放 / 红绿灯，按 data-window 与 manifest 落实尺寸。

load() 自带并发去重（内部一张 loadingMap）：同一个插件正在加载时，重复点击复用同一个 Promise，不会注两份。

缓存戳的真实语义（有意为之，别「修」它）

资源戳值语义
manifest.json?v=VERSION随发布失效，同一发布内复用缓存
style.css / index.html内置 ?v=VERSION；商店 ZIP 插件 Date.now()ZIP 允许同 id 覆盖安装，必须每次取新
script.js（入口）永远 Date.now() + 递增序号入口顶层要重跑 init()；URL 稳定会被 ES module 缓存命中 →「第二次打开不执行」

两条硬约束（代价：模块表不回收旧实例）

  1. 入口脚本每次打开都重跑 → 它注册的全局资源（document/window 监听、定时器、轮询、window.__* 钩子、__menuActions 键） 必须在 plugin-unload 回调里亲手释放。旧脚本元素被移除了，但它注册的监听器不会跟着消失，会永久累积。 内置示范：calculator / notepad / photos / launchpad / vs_code 的 script.js 里都有这个监听。
  2. 被 import 的子模块只有一份实例（URL 稳定，跨打开复用）→ 入口的 init() 必须自己复位状态、对订阅去重。 不能假设「这次打开 = 干净状态」。

卸载与生命周期事件

事件detail什么时候发
plugins-ready{plugins}注册表就绪（内置插件全部注册 + ZIP 还原完成）
plugin-registered完整 manifest 对象每个插件注册时（权限账本的 grantAll 挂在这里）
plugin-unload{id}单应用插件关窗 / 多应用插件没有存活窗口时；系统随后移除样式与脚本元素。你的全局监听、定时器都在这个回调里释放
plugin-app-load{id, appId, windowName, el}多应用插件：每个应用窗口就绪（外壳只在第一个应用时注过一次）
plugin-app-unload{id, appId}多应用插件：关掉其中一个应用窗口（外壳还在）
plugin-app-open{id, appId, windowName, file}访达双击带文件打开；窗口已存在也会派发（换文件复用窗口）
plugin-unregistered{id}插件被卸载/移除（权限账本在这里清账）

这些事件都在 document 上派发（bubbles: true），所以在 window 或 document 上监听都能收到——内核两种写法都有，保持一致即可。

调试技巧 顶栏「调试 → 重载当前插件」= 关窗再开窗，专门用来验证你的 plugin-unload 清没清干净： 重载后如果界面叠了两层、菜单项多了一倍、日志重复打印，就是有资源没释放。
