插件包格式

manifest 字段全表（以代码读取方为准）、多应用插件、图标与路径硬规则、store 自声明、ZIP 打包。

固定目录结构

mods/{id}/
├── manifest.json   # 插件清单（唯一事实来源）
├── index.html      # 窗口/界面 HTML 片段（恰好一个 .window 根）
├── style.css       # 样式
├── script.js       # 逻辑（ES Module）
└── icon.png        # 图标（Dock / 启动台 / 商店共用）

id 命名：小写蛇形（vs_code、system-settings），只允许 [A-Za-z0-9][A-Za-z0-9._-]* 且不含 ..——id 直接拼进 ./mods/<id>/ 路径与 script[plugin=<id>] 选择器，非法即拒注册。

manifest 字段（「读取方」列以代码 grep 为准）

字段必填说明
id✅唯一标识：注册表键 + 资源路径拼接
name✅显示名（Dock / 启动台 / 菜单 / 商店）；多应用时也是窗口去重键
entry✅window | fullscreen；启动台只列 window
main / style / script✅缺省 index.html / style.css / script.js；经 safeAssetName() 校验
icon 见「图标规则」；不声明则落 GENERIC_APP_ICON 占位
window.* width / height / resizable / centered；被 data-window 覆盖（后者为准）
apps[] 多应用插件声明，见下节
menus 顶栏菜单自定义：{"文件":[{label, i18nKey?, shortcut?, cmd?, disabled?}]}；只整组替换声明过的标题，未声明的保留宿主默认集
version 商店卡片 v<ver> 与安装记账；不做自动更新比对（没有远程源）
type 只有 app；启动台按它过滤，plugin-manager 不读
description 商店卡片/详情的缺省文案（store.tagline/summary 没写时）；plugin-manager 不读
author 根级这个字段是死的（无任何读取方）；商店详情显示作者写 store.author
store 商店自声明区块，见下节
formats 根级是纯文档字段（无人读取）；接管文件类型只认 apps[].formats
permissions✅取值必须来自 api-grants.js 的 15 条 PERMISSION_NAMES； 没声明的能力调用直接 ok:false；哪怕无能力也要写 "permissions": []（static-check 第 7 节核对）
_installed 安装/还原流程写入的内部标记，非用户可填

多应用插件（apps[]，参考实现 mods/office/）

  • appId = <插件id>.<app.id>（如 office.word）；
  • 每个应用一个 HTML 片段（缺省 <app.id>.html），片段恰好一个 .window 根；宿主把其 id 写成 app.windowName || app.name —— 所以应用显示名不能互相撞（窗口 id 是去重键）；
  • 外壳只注入一次：首个应用打开时注 style + script，之后每个应用只注自己的片段。 script.js 顶层只允许登记全局监听与菜单命令，界面初始化必须写在 plugin-app-load 回调里 （detail = {id, appId, windowName, el}）—— 与单应用「顶层直接 init()」相反，别照搬；
  • 关单个应用发 plugin-app-unload；整个插件无存活窗口时才发 plugin-unload（按 .window[data-plugin-id] 存活数引用计数）；全局资源只在该事件里释放；
  • apps[].formats（如 [".docx", ".txt"]，带不带点都行）声明能打开的扩展名： 访达双击经 getAppByExtension() 问路 → openApp(appId, {file}) + 派发 plugin-app-open （detail = {id, appId, windowName, file}，窗口已存在时也派发）。只有实现了 plugin-app-open 的应用才该声明 formats；没命中时访达原样退回 Quick Look。

图标（硬性四条）

  1. 应用图标一律 PNG，禁 SVG（Dock/启动台/商店共用同一张位图；菜单栏单色 glyph 如 siri 的 icon.svg 不受限）；
  2. 新应用图标先到 assets/icons/ 找（含 dock/、folder/ 子目录）；
  3. 找到就复制进插件目录，manifest 只写裸文件名（ZIP 要求自包含；不要把库里原文件移走—— dock.js 的 iconMap 按名字兜底引用整个库）；
  4. 没有合适的就不声明——系统自动落 GENERIC_APP_ICON（assets/icons/dock/Launcher.png）， 三处 img.onerror 都回退它；占位图只有一个来源，别在别处再写死路径。

解析顺序：manifest.icon（权威）→ ./mods/<id>/icon.png（目录约定兜底）→ 占位图。 apps[].icon 优先于插件级 icon，再落回上述三级（套件缺图显示套件图标，不是占位）。

相对路径约定

引用目标写法
根图片 / 根图标 / 共享 JS / 共享 UI../../assets/images/… / ../../src/javascripts/…
  • ../../ 只对两类必需：import 说明符与 CSS url()（相对文件自身解析）；
  • JS 运行时 URL（<img src>、fetch()、Notification.icon）相对文档解析—— 插件里写 ../../assets/… 只是被截断回根、看着能用实为巧合。因此 JS 内资源路径一律 import { assetPath, modPath } from "../../src/javascripts/paths.js"；
  • import 说明符不带 ?v=（双模块分裂陷阱，见架构）。

商店自声明（store）

"store": {
  "category": "办公", "tagline": "…", "summary": "…",
  "features": ["能力一"], "usage": "…", "updated": "2026-10-26",
  "author": "…", "homepage": "https://…",
  "screenshots": ["screens/one.png"]
}
  • 只渲染声明了的区块，没写的区块不出现（界面不编文案）；全部 textContent 写入（清单不可信，不解析 HTML）；
  • 清洗限额（store-api.js:storeMeta()）：category 24 字、tagline 120、summary/usage 600、author 60、updated 20、features ≤12 条×120 字；
  • screenshots 是插件目录内相对路径（宿主拼 ./mods/<id>/<file> 加 ?v=），只收 png/jpg/jpeg/webp、拒 ..、截前 6 张；取不到不算安装失败（optionalMissing），但 dev/package-plugin.mjs 会因此拒绝打包；
  • homepage 只收 http(s)://；权限不写在 store 里——详情页权限栏读 manifest.permissions，经 api-grants.describe() 出文案，与授权账本同源。

打包分发（ZIP）

node dev/package-plugin.mjs <id>      # 产物 dist/<id>-<version>.zip
  • 唯一真源是 mods/<id>/；ZIP 只是导出物（避免「改了 mods 却拿旧 ZIP 去装」的分裂）；
  • 包内 manifest.json 必须在包根或同一顶层目录（commonRoot() 判公共根）；包内条目一律 POSIX /（不用 Compress-Archive——它的反斜杠条目 SW 命中不了）；解包总字节 ≤ 10MB；
  • 打包即校验：id 必须等于目录名、相对依赖必须落在插件目录内、宿主依赖（../../src/…）必须存在于仓库；少打一个文件在运行时只会表现为「窗口开了但空白」，这一关必须在构建期断掉。
