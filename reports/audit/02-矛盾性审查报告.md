## 2. 审查方法与判断依据

1. 接口比对：先清点宿主实际暴露面，再机械扫描插件侧全部调用，逐一核对存在性、参数、返回值结构。
2. 声明比对：manifest 权限/host_permissions/版本号 vs 代码实际 API 调用与 fetch 目标。
3. 文档比对：devdocs 各页断言逐条与代码对读；对「承诺有机器门禁」类断言实跑对应脚本验证。
4. i18n 比对：四语言包键集互 diff，再与 JS 引用键集合求差。
5. 样式比对：机械提取全部 `--var` 定义与 `var()` 引用求差；主题切换所写的 data 属性/类名与 CSS 选择器互查。
6. 注释比对：对含「已修复/不再/必须/同一语义/行号引用」的注释逐条回读被指代码验证。
7. 收录标准：必须能同时给出矛盾双方的文件+行号+片段；单方可疑但无对照证据的不收。
