日志 __log

可查、可留存、可导出的运行记录；300+ 处裸 console.* 已被自动归档。

方法

方法说明
info/warn/error/debug(source, msg, data?)按级别写一条；被门槛过滤时返回 null
entry(level, source, msg, data?)级别是变量时的统一入口；非法级别按 info 归档
for(source)绑定来源的子日志器（.info/.warn/.error/.debug/.entry/.timer）
timer(label)timer("首屏").stop() 以 info 记毫秒差并返回数字
assert(cond, source, msg)不成立记 error 并返回 false
query(opts?) / recent(n=100) / count() / stats()条件筛选 / 最近 n 条（时间正序）/ 条数 / 分级分来源统计（含 capacity、dropped）

门槛与来源分类

  • 六个调试项由 log.js 自注册：debug.logLevel（门槛）/ debug.bufferSize / debug.persist / debug.captureConsole / debug.captureErrors / debug.persistCount。 默认门槛是 info——你写的 debug 不出现是门槛滤掉的，不是丢了；排查时先 __settings.set("debug.logLevel","debug")。
  • 来源统一带类别前缀：已含斜杠的照用；裸名按内核模块白名单判定，未命中一律归 plugin/。 插件请显式写 plugin/<你的id>——哪天内核加了同名模块，你的日志会静默跑进 kernel/ 里，「按程序分类」维度就废了。
const log = __log.for("plugin/my-plugin");
log.info("界面就绪");            // → source = "plugin/my-plugin"
log.timer("首屏").stop();

缓冲与留存

缓冲在内核（跨窗口、跨刷新）；已写的代码不必改造——console.* 在 log.js 求值时就被包了一层， 先归档再原样输出，浏览器控制台行为不变。应用内查看：顶栏「调试 → 查看运行记录」 （清空 / 导出文件 / 复制剪贴板 / 切门槛 / 重载当前插件都在那个菜单里）。
